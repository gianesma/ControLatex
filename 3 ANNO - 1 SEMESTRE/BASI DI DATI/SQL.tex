\subsection{Select}
L'istruzione di interrogazione in SQL è \texttt{select} che definisce una interrogazione (query) e restituisce il risultato della valutazione di quella query sulla base di dati in forma di tabella. La sua forma elementare è:
\begin{verbatim}
    select  Attributo,...,Attributo
    from    Tabella
    where   Condizione
\end{verbatim}
\noindent semantica:\\
ogni tupla $t$ della Tabella è indicata nella clausola \underline{from} viene analizzata. Se $t$ non soddisfa la condizione nella clausola \underline{where}, allora viene ignorata. 
Altrimenti da $t$ viene prodotta la target list (lista attributi) secondo quanto specificato nella target list che appare dopo \underline{select} e la tupla risultante da tale target list viene inserita nel risultato. 
Il risultato della esecuzione della query viene restituito nel canale di output del sistema e volendo memorizzarlo nella base di dati.
La semantica descritta chiarisce che l'istruzione è analoga alla seguente espressione dell'algebra relazionale\\
$$PROJ_{Attributo,...,Attributo}(SEL_{Condizione}(Tabella))$$\\
Diciamo analoga e non equivalente perchè in sql la tabella può avere duplicati.\\

\section{Ridenominazione As}
"as" nella lista degli attributi serve a ridenominare gli attributi, specificando esplicitamente un nome per un attributo del risultato.\\
\textcolor{verdeEsempio}{Esempio:}
\begin{verbatim}
select nome as name, reddito as salary
from persone
where eta<30
\end{verbatim}
\noindent restituisce com risultato una tabella con due attributi, il primo nome name ed il secondo salary.\\
"as" serve anche ad assegnare un nuovo nome alle tabelle nel'ambito di una query.\\
\textcolor{verdeEsempio}{Esempio:}
\begin{verbatim}
select p.nome as name, p.reddito as salary
from persone as p
where p.eta<30
\end{verbatim}
\section{Distinct, $<$, *, where, null}
\subsection{Distinct}
Per non avere duplicati nella query nella select aggiungiamo distinct\\
\textcolor{verdeEsempio}{Esempio:}\\
\texttt{select distinct attributo1,...,attributo2 from tabella1}
\subsection{$<$}
La utilizziamo per evitare ridondanze quando stiamo confrontando righe della stessa tabella tra loro, tipicamente in un self join, e vogliamo ottenere ogni coppia una sola volta.\\
\textcolor{verdeEsempio}{Esempio:}
\begin{verbatim}
    select p1.nome, p2.nome
    from persona p1, persona p2
    where p1.id < p2.id
\end{verbatim}
\subsection{*}
Qunado vogliamo che una query restituisca tutti gli attributi usiamo '*' nella select al posto della lista degli attributi.\\
\textcolor{verdeEsempio}{Esempio:}\\
Data una tabella R sugli attributi A1,...,An:\medskip\\
\begin{minipage}[c]{0.40\textwidth}
       \begin{verbatim}
        select *
        from tabella1
        where condizione
        \end{verbatim}
    \end{minipage}
    equivale a
    \begin{minipage}[c]{0.25\textwidth}
        \begin{verbatim}
            select A1,...,An
            from R
            where condizione
        \end{verbatim}
\end{minipage}
\subsection{Condizione while}
Quando eseguiamo una query in cui non c'è una condizione possiamo scrivere while true o non scrivere proprio where.\\
\textcolor{verdeEsempio}{Esempio:}\\
\begin{minipage}[c]{0.40\textwidth}
       \begin{verbatim}
        select A1,...,An
        from tabella1
        \end{verbatim}
    \end{minipage}
    equivale a
    \begin{minipage}[c]{0.25\textwidth}
        \begin{verbatim}
            select A1,...,An
            from R
            where true
        \end{verbatim}
\end{minipage}\medskip\\
Nella clausola where possono comparire espressioni booleane qualunque\\
\textcolor{verdeEsempio}{Esempio:}\\
\texttt{select *
from persone
where reddito > 25 and (eta < 30 or eta >60)}\\
Nelle condizioni nella clausola where si possono usare molti operatori che SQL mette a disposizione.\\
Ad esempio l'operatore \texttt{like} che consente di verificare che una stringa appartenga al linguaggio definito da una espressione regolare.\\
\textcolor{verdeEsempio}{Esempio:}\\
se vogliamo conoscere quali sono le persone che hanno un nome che inizia per 'A', ha 'd' come terza lettera e può continuare con altri caratteri.
\begin{verbatim}
select *
from persone
where nome like 'A_d%'
\end{verbatim}
\subsection{gestione dei valori nulli - "is null" e "is not null"}
nelle condizioni che compaiono nella clausola where si possono usare anche i predicati "is null" e "is not null" per gestire i valori nulli\\
\textcolor{verdeEsempio}{Esempio:}\\
vogliamo le persone la cui eta è o ptrebbe essere maggiore di 40
\begin{verbatim}
select *
from persone
where eta > 40 or eta is null    
\end{verbatim}
\section{Espressioni nella target list}

\textcolor{verdeEsempio}{Esempio:}\\
\texttt{select eta, reddito/2\\
from persone\\

\textcolor{verdeEsempio}{Esempio:}\\
\texttt{select 'Gigi' as nomePersona, eta, reddito/2 as redditoSemestrale\\
from persone\\
where nome='Luigi'}\\
Espressione costituita da una costante di tipo stringa che aggiunge un attributo nomePersona con la stringa 'Gigi'\\

\section{Selezione, proiezione e join}
le istruzioni select che abbiamo visto finora hanno una sola tabella nella clausola from e quindi permettono di realizzare:
\begin{itemize}
    \item selezioni
    \item proiezioni
    \item ridenominazioni
\end{itemize}
\noindent I joni si possono realizzare indicando due o più tabelle nella clausola from, separate da virgola
\subsection{Select}
\subsubsection{sintassi e semantica}
La forma base delle selct in SQL è:
\begin{verbatim}
    select <target list>  --> lista attributi
    from R1,R2,...,Rn
    where <condizione>
\end{verbatim}
\noindent In algebra relazionale: $PROJ_{target list}(SEL_{<condizione>}(R_1 \times R_2 \times ... \times R_n))$\\
Ogni tupla t del prodotto cartesiano viene analizzata. Se t non verifica la condizione della clausola WHERE, essa viene ignorata. Se invece t verifica la condizione della clausola 
WHERE, allora da t viene prodotta la target list secondo la proiezione specificata nella clausola SELECT e la tupla risultante da tale target list viene inserita nel risultato\\
\underline{Attenzione}: questo non significa che il DBMS calcola il prodotto cartesiano di R1,R2,..,Rn. Significa che ilrisultato ottenuto è lo stesso di quello che si ottiene partendo dal prodotto cartesiano.
\subsection{Join}
Date due relazioni: R1(A1, A2) e R2(A3, A4)
\begin{verbatim}
    select R1.A1, R2.A4
    from R1, R2
    where R1.A2 = R2.A3
\end{verbatim}
\noindent è analoga a: $PROJ_{A1,A4}(R1 \text{ }JOIN_{A2=A3}\text{ }R2)$\\
Possono essere necessarie ridenominazioni:
\begin{itemize}
    \item nella target list
    \item nella clausola from (in particolare, introdurre alias consente di riferirsi due o più volte alla stessa tabella)
\end{itemize}
\noindent \textcolor{verdeEsempio}{Esempio:}
\begin{verbatim}
    select X.A1 as B1,...
    from R1 as X, R2 as Y, R1 as Z
    where X.A2 = Y.A3 and Y.A4 = Z.A1
\end{verbatim}
\noindent Si può anche scireve senza 'as'.\medskip\\
Date le tabelle R1(A1, A2) e R2(A3, A4)
\begin{verbatim}
    select distinct X.A1 as B1, Y.A4 as B2
    from R1 as X, R2 as Y, R1 as Z
    where X.A2 = Y.A3 and Y.A4 = Z.A1 
\end{verbatim}
\noindent è equivalente a:
$REN_{B1,B2 \leftarrow A1,A4}( PROJ_{A1,A4} (SEL_{A2=A3 \text{ and }A4=C1 }( R1 \text{ }JOIN\text{ }R2\text{ }JOIN\text{ }REN_{C1,C2 \leftarrow A1,A2}(R1))))$
\subsection{Self-join}
Il self-join è un join in cui la stessa relazione compare sia come operando sinistro sia come operando destro ed è cruciale quando dobbiamo combinare due tuple della stessa relazione.\\
\textcolor{verdeEsempio}{Esempio:}\\
\texttt{persone(nome, eta, reddito)}\\
\underline{query}: Vogliamo le coppie di persone con lo stesso reddito\\
\underline{soluzione}:
\begin{verbatim}
    select p1.nome, p1.eta, p1.reddito, p2.nome, p2.eta
    from persone p1, persone p2
    where p1.reddito=p2.reddito and p1.nome<p2.nome
\end{verbatim}
\noindent utilizziamo p1.nome $<$ p2.nome per eliminare le tuple ridondanti, in quando lascia solo le tuple in cui p1.nome viene prima in ordine alfabetico di p2.nome

\subsection{Join multipli}

Quando una query richiede di mettere in relazione informazioni provenienti da più tabelle, è possibile eseguire \textbf{più join nella stessa interrogazione}. L'idea è costruire progressivamente il risultato: ogni join collega una nuova tabella al risultato ottenuto dai join precedenti attraverso una specifica condizione.
Un primo esempio riguarda la ricerca del \textbf{padre e della madre di ogni persona della quale entrambi i genitori sono noti}. Le tabelle \texttt{paternita} e \texttt{maternita} possiedono entrambe l'attributo \texttt{figlio}, che permette di collegare le informazioni relative alla stessa persona:

\begin{verbatim}
select paternita.figlio, padre, madre
from maternita, paternita
where paternita.figlio = maternita.figlio
\end{verbatim}

\noindent In questo caso è sufficiente un solo join. Se, però, si vuole anche garantire che il figlio compaia effettivamente nella tabella \texttt{persone}, è necessario introdurre un \textbf{secondo join}:

\begin{verbatim}
select paternita.figlio, padre, madre
from maternita, paternita, persone
where paternita.figlio = maternita.figlio
  and paternita.figlio = persone.nome
\end{verbatim}

\noindent Quindi, quando sono presenti più join, nella clausola \texttt{from} vengono indicate tutte le tabelle coinvolte, mentre nella clausola \texttt{where} vengono specificate le condizioni che stabiliscono come collegarle tra loro. Ogni condizione di join permette di associare tuple che rappresentano entità correlate. 
Un caso più articolato si presenta quando la \textbf{stessa tabella deve essere utilizzata più volte con ruoli differenti}. L'esempio considerato è quello delle persone che guadagnano più dei rispettivi padri, mostrando il nome della persona, il suo reddito e il reddito del padre.
La tabella \texttt{persone} deve comparire due volte: una volta per rappresentare il \textbf{padre} e una volta per rappresentare il \textbf{figlio}. Per distinguere le due occorrenze si utilizzano degli \textbf{alias}:

\begin{verbatim}
select f.nome, f.reddito as reddito,
       p.reddito as redditoPadre
from persone p, paternita t, persone f
where p.nome = t.padre
  and t.figlio = f.nome
  and f.reddito > p.reddito
\end{verbatim}

\noindent Gli alias hanno quindi un ruolo fondamentale:
\begin{itemize}
    \item \texttt{p} rappresenta la persona nel ruolo di \textbf{padre};
    \item \texttt{t} rappresenta la tabella \texttt{paternita};
    \item \texttt{f} rappresenta la persona nel ruolo di \textbf{figlio}.
\end{itemize}

\noindent I join vengono concettualmente costruiti in più passaggi. Prima si collega \texttt{paternita} alla copia di \texttt{persone} che rappresenta il figlio, mediante la corrispondenza

\[
\texttt{t.figlio = f.nome}.
\]

\noindent In questo modo si ottengono insieme le informazioni sulla relazione di paternità e quelle relative al figlio. Successivamente si collega anche la copia di \texttt{persone} che rappresenta il padre:

\[
\texttt{p.nome = t.padre}.
\]

\noindent A questo punto ogni tupla contiene le informazioni necessarie sia sul figlio sia sul relativo padre. È quindi possibile applicare la condizione

\[
\texttt{f.reddito > p.reddito},
\]

\noindent che mantiene solamente i casi in cui il reddito del figlio è maggiore di quello del padre. Infine, con la \texttt{select} vengono mantenuti solamente gli attributi richiesti: nome del figlio, reddito del figlio e reddito del padre.
In generale, quindi, una query con \textbf{più join} può essere vista come una costruzione progressiva: si collegano prima due tabelle, il risultato viene poi collegato a un'altra tabella e così via. Se una stessa tabella deve rappresentare entità con ruoli differenti, la si inserisce più volte nella query assegnandole alias diversi. Le condizioni nella clausola \texttt{where} stabiliscono sia i collegamenti tra le varie occorrenze delle tabelle sia gli eventuali ulteriori criteri di selezione.

\subsection{Join esplicito}
\begin{verbatim}
select ...
from Tabella1 join Tabella2 on CondJoin,...
[where AltraCondizione]
\end{verbatim}

\noindent La parola chiave \texttt{join} specifica le tabelle da combinare, mentre la clausola \texttt{on} contiene la \textbf{condizione di join}, cioè la condizione che stabilisce quali tuple delle due tabelle devono essere associate. La clausola \texttt{where}, invece, può essere utilizzata per imporre ulteriori condizioni sul risultato del join.\\
\textcolor{verdeEsempio}{Esempio} per ottenere padre e madre delle persone per le quali entrambi i genitori sono noti, invece di scrivere:
\begin{verbatim}
select paternita.figlio, padre, madre
from maternita, paternita
where paternita.figlio = maternita.figlio
\end{verbatim}
\noindent si può utilizzare il join esplicito:
\begin{verbatim}
select madre, paternita.figlio, padre
from maternita join paternita on
     paternita.figlio = maternita.figlio
\end{verbatim}
\noindent In questo caso si tratta di un \textbf{equi-join}, perché la condizione specificata dopo \texttt{on} è un'uguaglianza.
Il join esplicito può essere applicato \textbf{più volte consecutivamente}. Il risultato di un primo join è infatti una nuova tabella, che può essere utilizzata come operando di un secondo join.\\ 
\textcolor{verdeEsempio}{Esempio:}
\begin{verbatim}
select f.nome, f.reddito, p.reddito
from persone p
     join paternita t on p.nome = t.padre
     join persone f on t.figlio = f.nome
where f.reddito > p.reddito
\end{verbatim}
\noindent Il primo join:
\begin{verbatim}
persone p join paternita t on p.nome = t.padre
\end{verbatim}
\noindent collega ogni padre alla relativa informazione nella tabella \texttt{paternita}. Il risultato viene poi utilizzato nel secondo join:
\begin{verbatim}
join persone f on t.figlio = f.nome
\end{verbatim}
\noindent che associa anche le informazioni relative al figlio. Solo dopo aver costruito questi collegamenti viene applicata la condizione:
\begin{verbatim}
where f.reddito > p.reddito
\end{verbatim}
\noindent per mantenere i figli che guadagnano più del rispettivo padre.
È importante osservare che il \textbf{risultato di un join contiene gli attributi di entrambi gli operandi}. Di conseguenza, se si eseguono più join consecutivi, ogni risultato intermedio accumula gli attributi delle tabelle coinvolte.
Nella query sopra, il primo join esplicito nella clausola fromdà come risultato
una tabella con gli attributi: \texttt{p.nome, p.eta, p.reddito, t.padre. t.figlio}. Questa
tabella va in input al secondo join esplicito il cui risultato avrà come attributi:
\texttt{p.nome, p.eta, p.reddito, t.padre. t.figlio, f.nome, f.eta, ed f.reddito}.\\
In sintesi, il join esplicito permette di separare chiaramente le \textbf{condizioni che servono a collegare le tabelle}, scritte nella clausola \texttt{on}, dalle \textbf{condizioni che servono a filtrare il risultato}, che possono essere scritte nella clausola \texttt{where}. Inoltre, più join possono essere concatenati, utilizzando ogni risultato intermedio come operando del join successivo.
\subsection{Ridenominazione del risultato di un join esplicito}
Poiché il risultato di un join esplicito è una \textbf{tabella}, esso può essere utilizzato direttamente nella clausola \texttt{from} e può anche essere \textbf{ridenominato assegnandogli un alias}.
Riprendiamo l'esempio precedente. Il primo join era:
\begin{verbatim}
persone p join paternita t on p.nome = t.padre
\end{verbatim}
\noindent Questo join produce una tabella contenente gli attributi di entrambi gli operandi:
\[
p.nome,\ p.eta,\ p.reddito,\ t.padre,\ t.figlio.
\]
\noindent È possibile assegnare un alias, ad esempio \texttt{J}, all'intero risultato del join:
\begin{verbatim}
from (persone p join paternita t on p.nome = t.padre) as J,
     persone f
\end{verbatim}
\noindent Quando si assegna un alias a un join esplicito è necessario \textbf{racchiudere tra parentesi l'intera espressione di join}.
Un aspetto importante è la \textbf{visibilità degli alias}. Gli alias \texttt{p} e \texttt{t}, definiti all'interno delle parentesi, non sono più
referenziabili all'esterno. All'esterno delle parentesi è visibile solamente l'alias \texttt{J}.
Di conseguenza, invece di riferirsi agli attributi attraverso \texttt{p} e \texttt{t}, bisogna utilizzare \texttt{J}.\\ 
\textcolor{verdeEsempio}{Esempio:}
\begin{verbatim}
where f.reddito > J.reddito
  and f.nome = J.figlio
\end{verbatim}
\noindent In questo caso:
\[
\texttt{J.reddito}
\]

\noindent indica l'attributo \texttt{reddito} proveniente dalla tabella \texttt{persone p}, mentre
\[
\texttt{J.figlio}
\]

\noindent indica l'attributo \texttt{figlio} proveniente dalla tabella \texttt{paternita t}. La query può quindi essere scritta come:
\begin{verbatim}
select f.nome, f.reddito, J.reddito
from (persone p join paternita t on p.nome = t.padre) as J,
     persone f
where f.reddito > J.reddito
  and f.nome = J.figlio
\end{verbatim}
\noindent L'alias \texttt{J} deve quindi essere visto come il \textbf{nome della nuova tabella prodotta dal join}, che eredita gli attributi delle tabelle utilizzate
per costruirla.

\subsection{Ridenominazione degli attributi del risultato}
Quando la struttura dei join diventa più complessa, assegnare soltanto un nome
al risultato può non essere sufficiente. SQL permette quindi di specificare,
oltre al nome della nuova tabella, anche i \textbf{nomi dei suoi attributi}.\medskip\\
Ricordando che il database è così composto:
\begin{verbatim}
persone(nome, eta, reddito): contiene le informazioni sulle persone.
paternita(padre, figlio): rappresenta le relazioni padre-figlio.
maternita(madre, figlio): rappresenta le relazioni madre-figlio.
\end{verbatim}
\noindent Supponiamo ora di volere le coppie (senza ridondanze) di persone diverse
che hanno la stessa età e sono figli dello stesso padre.
Vogliamo utilizzare un join tra due join espliciti, uno per individuare le coppie
di persone diverse con la stessa eta (alias F) e l’altro per individuare le
coppie di tuple di paternita con lo stesso valore per “figlio".
Consideriamo un join tra due occorrenze della tabella \texttt{persone}:
\begin{verbatim}
persone r join persone s
on r.eta = s.eta and r.nome < s.nome
\end{verbatim}

\noindent Il risultato possiede sei attributi, cioè i tre attributi di \texttt{r} seguiti
dai tre attributi di \texttt{s}. Possiamo ridenominare l'intero risultato e,
contemporaneamente, i suoi attributi:
\begin{verbatim}
(persone r join persone s
 on r.eta = s.eta and r.nome < s.nome)
as F(n1,e1,r1,n2,e2,r2)
\end{verbatim}

\noindent L'alias non è quindi più soltanto \texttt{F}, ma specifica anche lo schema
della tabella risultante:
\[
F(n1,e1,r1,n2,e2,r2).
\]

\noindent I nomi vengono assegnati agli attributi rispettando il loro ordine. Quindi,
ad esempio, il primo attributo \texttt{r.nome} diventa \texttt{F.n1}, mentre
\texttt{s.nome} diventa \texttt{F.n2}.
Lo stesso meccanismo può essere applicato a un altro join:
\begin{verbatim}
(paternita p join paternita t on p.padre = t.padre)
as S(p1,f1,p2,f2)
\end{verbatim}

\noindent A questo punto i risultati dei due join possiedono attributi con nomi
esplicitamente definiti e possono essere a loro volta messi in join:
\begin{verbatim}
select F.n1, F.n2
from (persone r join persone s
      on r.eta = s.eta and r.nome < s.nome)
     as F(n1,e1,r1,n2,e2,r2)
join
     (paternita p join paternita t
      on p.padre = t.padre)
     as S(p1,f1,p2,f2)
on F.n1 = S.f1 and F.n2 = S.f2
\end{verbatim}

\noindent La ridenominazione degli attributi permette quindi di utilizzare senza ambiguità gli attributi dei \textbf{risultati intermedi dei join}, anche
quando si costruisce un join tra risultati di altri join espliciti.

\subsection{Natural Join}
SQL mette a disposizione il \textbf{natural join}, che permette di effettuare
automaticamente un equi-join utilizzando gli attributi che le due tabelle
hanno in comune, cioè gli attributi con lo stesso nome semplice.\\
\textcolor{verdeEsempio}{Esempio:} considerando le tabelle \texttt{maternita} e \texttt{paternita},
entrambe possiedono l'attributo \texttt{figlio}.\\ Con il join esplicito si
scriverebbe:
\begin{verbatim}
select paternita.figlio, padre, madre
from maternita join paternita on
     paternita.figlio = maternita.figlio
\end{verbatim}
\noindent Utilizzando il \textbf{natural join}, invece, non è necessario specificare
esplicitamente la condizione di join:
\begin{verbatim}
select paternita.figlio, padre, madre
from maternita natural join paternita
\end{verbatim}
\noindent SQL riconosce automaticamente che \texttt{figlio} è un attributo comune alle
due tabelle e utilizza la condizione:
\[
\texttt{paternita.figlio = maternita.figlio}.
\]
Il \texttt{natural join} può quindi essere visto come un \textbf{equi-join
automatico su tutti gli attributi che hanno lo stesso nome semplice} nelle
due tabelle.
Per \textbf{nome semplice} si intende il nome dell'attributo senza considerare
il nome della relazione o dello schema. 

\subsection{Prodotto cartesiano in SQL}
In algebra e in sql il join naturale tra due relazioni che non hanno attributi in comune corrisponde al prodotto cartesiano.\\
Per calcolare il prodotto cartesiano di due relazioni in SQL ci sono anche altre possibilità:
\begin{itemize}
    \item esprimendo il prodotto cartesiano in modo implicito, mettendo le due relazioni nella lista dopo la clausola from
    \item esprimendo il prodotto cartesiano in modo esplicito, usando l'operatore di nome \texttt{cross join} nella clausola from
\end{itemize}
\textcolor{verdeEsempio}{Esempio:}\\
Vogliamo il prodotto cartesiano della tabella paternita e della tabella persona
\begin{itemize}
    \item Soluzione con il join naturale (visto che le due tabelle non hanno attributi in comune): \begin{verbatim}
        select * from paternita natural join persona        
    \end{verbatim}
    \item Soluzione con il prodotto cartesiano implicito (lista nella form): \begin{verbatim}
        select * from paternita, perosna
    \end{verbatim}
    \item Soluzione con il prodotto cartesiano esplicito (cross join): \begin{verbatim}
        select * from paternita cross join persona
    \end{verbatim}
\end{itemize}

\newpage \subsection{Join esterno}
Il \textbf{join naturale esterno (outer join)} estende con valori nulli le tuple che non si accoppiano nel join: 
tali tuple verrebbero tagliate fuori da un join normale ed invece appaiono nel join esterno, accoppiate con valori nulli\\
esistono tre versioni:
\begin{itemize}
    \item \textbf{join esterno sinistro}: mantiene tutte le tuple del primo operando, estendendole con valori nulli, se necessario
    \item \textbf{join esterno destro}: mantiene tutte le tuple del primo operando, estendendole con valori nulli, se necessario
    \item \textbf{join esterno completo}: mantiene tutte le tuple sia del primo operando e sia del secondo operando, estendendole con valori nulli, se necessario
\end{itemize}
\noindent \textcolor{verdeEsempio}{Esempio:}\\
Padre di ogni persona e, se nota, anche la madre:
\begin{verbatim}
    select paternita.figlio, padre, madre
    from paternita left join maternita
         on paternita.figlio = maternita.figlio 
\end{verbatim}
\noindent \textcolor{verdeEsempio}{Esempio} con join completo in cui non perdo alcun figlio:
\begin{verbatim}
    select paternita.figlio, padre, madre, maternita.figlio 
    from paternita full outer join maternita 
         on paternita.figlio = maternita.figlio
\end{verbatim}

\section{Ordinamento, aggregazione e operazioni sui risultati delle query}
\subsection{Ordinamento del risultato: order by}
La clausola \texttt{ORDER BY} permette di \textbf{ordinare le tuple del risultato} di una query in base al valore di uno o più attributi.
La sintassi è:
\begin{verbatim}
order by attributo1, attributo2, ...
\end{verbatim}
\noindent Se non viene specificato diversamente, l'ordinamento è \textbf{crescente}.\\
\textcolor{verdeEsempio}{Esempio} vogliamo ottenere il nome e il reddito delle persone con meno di
30 anni, ordinandole prima in base al reddito e, a parità di reddito, in base al nome:
\begin{verbatim}
select nome, reddito
from persone
where eta < 30
order by reddito, nome
\end{verbatim}
\noindent L'ordinamento viene applicato seguendo l'ordine degli attributi indicati nella
clausola \texttt{ORDER BY}

\subsection{Limite alla dimensione del risultato: limit}
Si può indicare un limite alla dimensione del risultato con la clausola \texttt{limit} in SQL, al fine di avere come risultato al massimo un prefissato numero di tuple\\
\textcolor{verdeEsempio}{Esempio:}
\begin{verbatim}
select nome, reddito
from persone
where eta < 30
order by nome
limit 2
\end{verbatim}
\noindent otterremo una tabella con solo 2 tuple.

\subsection{Operatori aggregati}
Nelle espressioni della target list possiamo avere anche espressioni che calcolano valori a partire da insiemi di tuple:\\
\texttt{conteggio, minimo, massimo, media, totale}\\
Sintassi: \texttt{Funzione ([distinct] EspressioneSuAttributi)}\medskip\\
Quando un operatore aggregato ALFA compare nella target list di una query del tipo:
\begin{verbatim}
select <... ALFA ...>
from R1, R2,...,Rn
where <condizione>
\end{verbatim}
\noindent L'operatore aggregato viene applicato a tutte le tuple del prodotto cartesiano che soddisfano la condizione della clausola \texttt{where} ed il risultato sarà una 
singola tupla che conterrà il valore risultante o i valori risultanti dall'applicazione dell'operatore\\
\textcolor{verdeEsempio}{Esempio:}
\begin{verbatim}
select count(*)
from Persone
where eta > 30
\end{verbatim}
\noindent Tale query esegue i seguenti passi:\\
\begin{itemize}
    \item viene calcolato il prodotto cartesiano delle tabelle nella clausola \texttt{from}
    \item vengono selezionate le tuple della tabella che soddisfano la condizione nella clausola \texttt{where}
    \item viene applicato l'operatore aggregato (in questo caso \texttt{count(*)}) su tutte le tuple selezionate: viene quindi restituita 
            una tabella con una sola colonna ed una sola riga che contiene il risultato dell'applicazione dell'operatore aggregato, cioè il numero di tuple selezionate.
\end{itemize}
\subsubsection{count}
Sintassi:\\
\begin{itemize}
    \item conta il numero di tuple: \begin{verbatim}
        count(*)
    \end{verbatim}
    \item conta i valori di un attributo: \begin{verbatim}
        count (Attributo)
    \end{verbatim}
    \item conta i valori distinti di un attributo: \begin{verbatim}
        count (distinct Attributo)
    \end{verbatim}
\end{itemize}
\noindent \textcolor{verdeEsempio}{Esempio:} Quanti figli ha Franco?\\
\begin{verbatim}
select count(*) as NumFigliDiFranco
from paternita
where padre='Franco'
\end{verbatim}
\begin{center}
\begin{minipage}{0.45\textwidth}
    \centering
    \begin{tabular}{|c|c|}
        \hline
        \textbf{padre} & \textbf{figlio} \\ \hline
        Sergio & Franco \\ \hline
        Luigi & Olga \\ \hline
        Luigi & Filippo \\ \hline
        Franco & Andrea \\ \hline
        Franco & Aldo \\ \hline
    \end{tabular}
\end{minipage}
\hfil
\begin{minipage}{0.45\textwidth}
    \centering
    \begin{tabular}{|c|}
        \hline
        \textbf{NumFigliDiFranco} \\ \hline
        2 \\ \hline
    \end{tabular}
\end{minipage}
\end{center}
\noindent Il count applicato su un attributo specifico conta solo tuple in cui quell'attributo ha valore diverso da \texttt{NULL}

\subsubsection{Altri operatori aggregati}
\texttt{sum, avg, max, min}\\
Ammettono come argomento un attributo o un espressione (ma non '*'), sum e avg sono argomenti numerici o di tempo, mentre max e min sono argomenti su cui è definito un ordinamento.\\
\textcolor{verdeEsempio}{Esempio:} media dei redditi dei figli di Franco
\begin{verbatim}
select avg(reddito)
from persone join paternita on nome = figlio
where padre = 'Franco'
\end{verbatim}

\noindent Le \textbf{funzioni aggregate}, come
\[
\texttt{MAX}, \quad \texttt{MIN}, \quad \texttt{AVG}, \quad
\texttt{SUM}, \quad \texttt{COUNT},
\]
considerano un insieme di tuple e producono un \textbf{singolo valore}.
\textcolor{verdeEsempio}{Esempio} consideriamo la seguente interrogazione:
\begin{verbatim}
SELECT nome, MAX(reddito)
FROM persone;
\end{verbatim}
Questa interrogazione presenta un problema.\\
L'attributo \texttt{nome} viene infatti valutato \textbf{per ogni
singola tupla} della tabella, mentre
\[
\texttt{MAX(reddito)}
\]
viene calcolato considerando \textbf{tutte le tuple} della tabella e
restituisce un solo valore.
\textcolor{verdeEsempio}{Esempio} supponiamo di avere:
\begin{center}
\begin{tabular}{|c|c|}
\hline
\textbf{nome} & \textbf{reddito} \\ \hline
Anna   & 2000 \\ \hline
Marco  & 3500 \\ \hline
Luca   & 2500 \\ \hline
\end{tabular}
\end{center}
Il massimo reddito è
\[
\texttt{MAX(reddito)} = 3500.
\]
Ma quale nome dovrebbe essere restituito?
\[
(\text{Anna},3500), \qquad
(\text{Marco},3500), \qquad
(\text{Luca},3500)?
\]
La query non specifica quale tupla debba fornire il valore di
\texttt{nome}. Per questo motivo la \textbf{target list non è
omogenea}.\\
\noindent
\colorbox{SALZO}{\parbox{\dimexpr\linewidth-2\fboxsep}{\begin{regola}
Se utilizziamo funzioni aggregate senza \texttt{GROUP BY}, gli
elementi della \texttt{SELECT} devono essere omogenei: non possiamo
mescolare attributi riferiti alle singole tuple con valori aggregati
calcolati sull'intera tabella.\end{regola}}}\\
\textcolor{verdeEsempio}{Esempio} la seguente interrogazione è corretta:
\begin{verbatim}
SELECT MIN(eta), AVG(reddito)
FROM persone;
\end{verbatim}
In questo caso entrambi gli elementi della target list sono funzioni
aggregate:
\[
\texttt{MIN(eta)}
\qquad\text{e}\qquad
\texttt{AVG(reddito)}.
\]
Entrambe considerano l'insieme delle tuple e restituiscono un singolo
valore. La target list è quindi \textbf{omogenea}.

\subsection{group by}
Nei casi visti in precedenza, gli operatori aggregati sono applicati all'insieme di tutte le tuple che formano il risultato di una query.
In molti casi, vorremmo che le funzioni di aggregazione venissero applicate a \underline{gruppi di tuple} delle relazioni. Per specificare i gruppi di tuple su cui applicare le funzioni, si utilizza la clausola \texttt{group by}:
\begin{verbatim}group by listaAttributi\end{verbatim}

\noindent \textcolor{verdeEsempio}{Esempio} Supponiamo di avere la seguente tabella:

\begin{center}
\begin{tabular}{|c|c|c|}
\hline
\textbf{nome} & \textbf{dipartimento} & \textbf{reddito} \\ \hline
Anna  & Informatica & 2000 \\ \hline
Luca  & Informatica & 3000 \\ \hline
Marco & Vendite     & 2500 \\ \hline
Sara  & Vendite     & 3500 \\ \hline
\end{tabular}
\end{center}
Vogliamo conoscere il reddito medio \textbf{di ogni dipartimento}.
Scriviamo:
\begin{verbatim}
SELECT dipartimento, AVG(reddito)
FROM persone
GROUP BY dipartimento;
\end{verbatim}
\noindent La clausola \texttt{GROUP BY dipartimento} divide le tuple in gruppi
in base al valore di \texttt{dipartimento}.
Si formano quindi due gruppi:
\[
G_1 =
\{
(\text{Anna},\text{Informatica},2000),
(\text{Luca},\text{Informatica},3000)
\}
\]
e
\[
G_2 =
\{
(\text{Marco},\text{Vendite},2500),
(\text{Sara},\text{Vendite},3500)
\}.
\]
A questo punto \texttt{AVG(reddito)} viene calcolato
\textbf{separatamente su ciascun gruppo}.
Per Informatica:
\[
\frac{2000+3000}{2}=2500
\]
Per Vendite:
\[
\frac{2500+3500}{2}=3000.
\]
Il risultato finale sarà:
\begin{center}
\begin{tabular}{|c|c|}
\hline
\textbf{dipartimento} & \textbf{AVG(reddito)} \\ \hline
Informatica & 2500 \\ \hline
Vendite & 3000 \\ \hline
\end{tabular}
\end{center}
Quindi possiamo ricordare che:
\[
\boxed{\text{GROUP BY crea i gruppi e le funzioni aggregate
vengono applicate a ciascun gruppo}}
\]
\noindent Semantica di una query con GROUP BY\\
Consideriamo una query della forma:
\begin{verbatim}
SELECT <target list>
FROM R1, ..., Rn
WHERE <condizione>
GROUP BY A;
\end{verbatim}
Per comprenderne il funzionamento possiamo immaginare l'esecuzione
in diversi passaggi.\\
\textbf{1. Selezione delle tuple}
Per prima cosa consideriamo la parte:
\begin{verbatim}
FROM R1, ..., Rn
WHERE <condizione>
\end{verbatim}
Concettualmente, in questa fase possiamo ignorare temporaneamente
sia la \texttt{SELECT} finale sia la \texttt{GROUP BY}.
Otteniamo quindi tutte le tuple che soddisfano la condizione
specificata nella clausola \texttt{WHERE}.\medskip\\
\textbf{2. Formazione dei gruppi}
Successivamente entra in gioco:
\begin{verbatim}
GROUP BY A
\end{verbatim}
Le tuple ottenute al passo precedente vengono divise in gruppi.
Due tuple appartengono allo stesso gruppo se hanno
\textbf{lo stesso valore dell'attributo $A$}.\\
\textcolor{verdeEsempio}{Esempio} se scriviamo:
\begin{verbatim}
GROUP BY dipartimento
\end{verbatim}
tutte le persone appartenenti a Informatica vengono messe nello
stesso gruppo, tutte quelle appartenenti a Vendite in un altro
gruppo, e così via.
Più in generale, se scriviamo:
\begin{verbatim}
GROUP BY A, B
\end{verbatim}
due tuple appartengono allo stesso gruppo solamente se hanno
\textbf{lo stesso valore sia di $A$ sia di $B$}.\medskip\\
\textbf{3. Applicazione delle funzioni aggregate}
Una volta creati i gruppi, le funzioni aggregate presenti nella
\texttt{SELECT} vengono calcolate
\textbf{separatamente all'interno di ciascun gruppo}.\\
\textcolor{verdeEsempio}{Esempio:}
\begin{verbatim}
SELECT dipartimento, MAX(reddito)
FROM persone
GROUP BY dipartimento;
\end{verbatim}
calcola
\[
\texttt{MAX(reddito)}
\]
non sull'intera tabella, ma separatamente per ogni dipartimento.\medskip\\
\textbf{4. Produzione del risultato}
In generale, viene prodotta \textbf{una tupla del risultato per ogni
gruppo}.
La differenza fondamentale è quindi:
\[
\begin{array}{ccl}
\text{senza GROUP BY}
&\Rightarrow&
\text{aggregazione sull'intero insieme di tuple}
\\[2mm]
\text{con GROUP BY}
&\Rightarrow&
\text{aggregazione separata per ogni gruppo}
\end{array}
\]
\subsubsection{Idea fondamentale}
La clausola \texttt{GROUP BY} non calcola direttamente una funzione
aggregata.
Il suo compito è \textbf{dividere le tuple in gruppi}.
Successivamente, funzioni come \texttt{AVG}, \texttt{MAX},
\texttt{MIN}, \texttt{SUM} e \texttt{COUNT} vengono applicate
separatamente alle tuple appartenenti a ciascun gruppo.\medskip\\
\colorbox{SALZO}{\parbox{\dimexpr\linewidth-2\fboxsep}{\begin{regola}
In una interrogazione che fa uso di \textbf{group by}, dovrebbero comparire solo target list "omogenee", ovvero target list che comprendono, oltre a funzioni di aggregazione, solamente attributi
che compaiono nella group by.\end{regola}}}\medskip\\
\textcolor{verdeEsempio}{Esempio:}\\
Redditi delle persone, raggrupati per età (\underline{non raggionevole}, perchè la target list è disomogenea: potrebbero esistere più valori di reddito per le persone appartenenti allo stesso gruppo):\\
\texttt{ select \textcolor{verdeScuro}{eta}, \textcolor{red}{reddito}\\
from persone\\
group by \textcolor{verdeScuro}{eta}}\\
Redditi delle persone, raggruppati per età (\underline{ragionevole}, perchè per ogni gruppo c'è una sola media dei redditi):\\
\texttt{select \textcolor{verdeScuro}{eta}, \textcolor{verdeScuro}{avg}(reddito)\\
from persone\\
group by \textcolor{verdeScuro}{eta}}

\subsection{Condizione sui gruppi: having}
Si possono anche imporre le condizioni di \textbf{selezione sui gruppi}. Per effettuare la selezione sui gruppi si usa la clausola \texttt{having}, che deve apparire dopo la \texttt{group by} e che di fatto 
opera un taglio sulle tuple del risultato dalla group by.\\
\textcolor{verdeEsempio}{Esempio:} i padri i cui figli hanno reddito medio maggiore di 25\\
Ricordando che il database è così composto:
\begin{verbatim}
persone(nome, eta, reddito): contiene le informazioni sulle persone.
paternita(padre, figlio): rappresenta le relazioni padre-figlio.
maternita(madre, figlio): rappresenta le relazioni madre-figlio.
\end{verbatim}
\begin{verbatim}
    select padre, avg(f.reddito)
    from persone f join paternita
         on figlio = f.nome
    group by padre
    having avg(f.reddito) > 25
\end{verbatim}
\noindent I padri i cui figli sotto i 30 anni hanno un reddito medio
maggiore di 20.\\
\begin{verbatim}
    select t.padre, avg(f.reddito)
    from persone f join paternita t
         on f.nome = t.figlio
    where f.eta < 30                ----> condizione sulle tuple che vanno a formare i gruppi
    group by t.padre
    having avg(f.reddito) > 20      ----> condizione sulle tuple che rappresentano i gruppi 
\end{verbatim}

\subsection{Riassunto e ordine}
L'ordine sintattico è:
\begin{verbatim}
    select ListaAttributiOEspressioni
    from ListaTabelle
    [where CondizioniSemplici]
    [group by ListaAttributiDiRaggruppamento]
    [having CondizioniAggregate]
    [order by ListaAttributiDiOrdinamento]
    [limit numero]
\end{verbatim}

\subsection{Unione}
la \texttt{select} da sola non permette di eseguire l'unione. Serve un costrutto esplicito:
\begin{verbatim}
    select ...
    union [all]
    select ...
\end{verbatim}
\noindent La target list delle due select devono avere lo stesso numero di elementi\\
Consideriamo la seguente query:
\begin{verbatim}
SELECT padre, figlio
FROM paternita
UNION
SELECT madre, figlio
FROM maternita;
\end{verbatim}
\noindent L'operatore \texttt{UNION} combina i risultati delle due \texttt{SELECT}.
L'associazione tra le colonne avviene \textbf{in base alla loro posizione}
e non in base al loro nome.
In particolare:
\[
\begin{array}{ccc}
\text{\texttt{padre}} & \longleftrightarrow & \text{\texttt{madre}} \\
\text{\texttt{figlio}} & \longleftrightarrow & \text{\texttt{figlio}}
\end{array}
\]
Quindi la prima colonna della prima \texttt{SELECT} viene unita con la
prima colonna della seconda \texttt{SELECT}, mentre la seconda colonna
viene unita con la seconda.
Affinché sia possibile utilizzare \texttt{UNION}, le due \texttt{SELECT}
devono restituire lo \textbf{stesso numero di colonne} e le colonne
corrispondenti devono avere \textbf{tipi compatibili}.
Poiché la prima query utilizza gli attributi \texttt{padre} e
\texttt{figlio}, mentre la seconda utilizza \texttt{madre} e
\texttt{figlio}, bisogna stabilire quali siano i nomi delle colonne
della relazione risultante.
Questo comportamento può dipendere dal DBMS. In molti sistemi vengono
utilizzati i nomi derivanti dalla prima \texttt{SELECT}. Il risultato
potrebbe quindi avere colonne:
\[
(\texttt{padre},\texttt{figlio})
\]
anche se nella prima colonna sono presenti sia padri sia madri.
Per rendere più chiaro il significato della colonna è possibile utilizzare
un alias:
\begin{verbatim}
SELECT padre AS genitore, figlio
FROM paternita
UNION
SELECT madre AS genitore, figlio
FROM maternita;
\end{verbatim}
\noindent ottenendo una relazione del tipo:
\[
(\texttt{genitore},\texttt{figlio})
\]
La prima \texttt{SELECT} produce le coppie padre--figlio, ad esempio:
\[
\begin{array}{c|c}
\textbf{padre} & \textbf{figlio} \\ \hline
\text{Sergio} & \text{Franco} \\
\text{Luigi} & \text{Olga} \\
\text{Luigi} & \text{Filippo} \\
\text{Franco} & \text{Andrea}
\end{array}
\]
La seconda \texttt{SELECT} produce invece le coppie madre--figlio, ad
\textcolor{verdeEsempio}{Esempio:}
\[
\begin{array}{c|c}
\textbf{madre} & \textbf{figlio} \\ \hline
\text{Anna} & \text{Olga} \\
\text{Anna} & \text{Filippo} \\
\text{Maria} & \text{Andrea} \\
\text{Maria} & \text{Aldo}
\end{array}
\]
L'operatore \texttt{UNION} mette tutte queste tuple in un'unica relazione.
Se i nomi delle colonne vengono presi dalla prima \texttt{SELECT}, si può
ottenere:
\[
\begin{array}{c|c}
\textbf{padre} & \textbf{figlio} \\ \hline
\text{Sergio} & \text{Franco} \\
\text{Luigi} & \text{Olga} \\
\vdots & \vdots \\
\text{Anna} & \text{Olga} \\
\text{Anna} & \text{Filippo} \\
\text{Maria} & \text{Andrea} \\
\text{Maria} & \text{Aldo}
\end{array}
\]
Il fatto che \texttt{Anna} e \texttt{Maria} compaiano nella colonna
chiamata \texttt{padre} non significa che vengano considerate padri.
Il motivo è semplicemente che \texttt{UNION} opera in modo
\textbf{posizionale}:
\[
\boxed{
\text{prima  colonna} \leftrightarrow \text{prima colonna},
\qquad
\text{seconda colonna} \leftrightarrow \text{seconda colonna}
}
\]
Per questo motivo, dal punto di vista semantico, sarebbe più corretto
chiamare la prima colonna \texttt{genitore}.
\medskip
\noindent
\textbf{Nota:} \texttt{UNION} elimina eventuali righe duplicate.
Se si vogliono mantenere anche i duplicati bisogna utilizzare
\texttt{UNION ALL}.

\subsection{Differenza: EXCEPT}

L'operatore \texttt{EXCEPT} rappresenta la \textbf{differenza tra i risultati
di due query}.
La forma generale è:
\begin{verbatim}
SELECT ...
FROM ...
EXCEPT
SELECT ...
FROM ...
\end{verbatim}
\noindent Il risultato contiene le tuple prodotte dalla \textbf{prima SELECT} che
\textbf{non compaiono nel risultato della seconda SELECT}.
In termini insiemistici, se la prima query produce l'insieme $A$ e la
seconda produce l'insieme $B$, allora:
\[
A \ \texttt{EXCEPT} \ B = A \setminus B
\]
È importante osservare che la differenza \textbf{non è commutativa}:
\[
A \setminus B \neq B \setminus A
\]
\textcolor{verdeEsempio}{Esempio}
Consideriamo la query:
\begin{verbatim}
SELECT nome
FROM impiegato
EXCEPT
SELECT cognome AS nome
FROM impiegato;
\end{verbatim}
\noindent La prima query:
\begin{verbatim}
SELECT nome
FROM impiegato
\end{verbatim}
\noindent produce l'insieme dei \textbf{nomi degli impiegati}.\\
La seconda query:
\begin{verbatim}
SELECT cognome AS nome
FROM impiegato
\end{verbatim}
\noindent produce invece l'insieme dei \textbf{cognomi degli impiegati}.
Pertanto, l'intera query restituisce:
\[
\boxed{
\text{nomi degli impiegati che non compaiono anche come cognomi}
}
\]
Ad esempio, supponiamo di avere:
\[
A =
\{\text{Mario},\text{Luca},\text{Rossi},\text{Anna}\}
\]
come insieme dei nomi e:
\[
B =
\{\text{Rossi},\text{Bianchi},\text{Verdi}\}
\]
come insieme dei cognomi.
Allora:
\[
A \setminus B =
\{\text{Mario},\text{Luca},\text{Anna}\}
\]
poiché \texttt{Rossi} compare anche tra i cognomi e viene quindi escluso
dal risultato.\\
Come per \texttt{UNION}, le due \texttt{SELECT} devono avere lo
\textbf{stesso numero di colonne} e le colonne nelle stesse posizioni
devono avere tipi compatibili.
In questo esempio entrambe restituiscono una sola colonna:
\[
\begin{array}{ccc}
\text{\texttt{nome}} & \longleftrightarrow & \text{\texttt{cognome}}
\end{array}
\]
L'alias:
\begin{verbatim}
cognome AS nome
\end{verbatim}
\noindent rinomina la colonna \texttt{cognome} in \texttt{nome}. Tuttavia,
\textbf{non è l'alias a rendere possibile EXCEPT}: ciò che conta è che
le colonne corrispondenti siano compatibili.\\
\texttt{EXCEPT} e \texttt{EXCEPT ALL}\\
Normalmente:
\[
\boxed{\texttt{EXCEPT} \quad \Rightarrow \quad
\text{elimina i duplicati}}
\]
Quindi il risultato segue una semantica insiemistica.
Con:
\[
\boxed{\texttt{EXCEPT ALL} \quad \Rightarrow \quad
\text{tiene conto dei duplicati}}
\]
la differenza considera anche il numero di occorrenze delle tuple.
Ad esempio, se:
\[
A = \{a,a,a,b\}
\]
e:
\[
B = \{a\}
\]
allora con \texttt{EXCEPT} otteniamo:
\[
A \ \texttt{EXCEPT} \ B = \{b\}
\]
mentre con \texttt{EXCEPT ALL} otteniamo:
\[
A \ \texttt{EXCEPT ALL} \ B = \{a,a,b\}
\]
perché viene sottratta solamente una delle tre occorrenze di $a$.

\subsection{Intersezione: INTERSECT}
L'operatore \texttt{INTERSECT} permette di calcolare
l'\textbf{intersezione tra i risultati di due query}.\\
La forma generale è:
\begin{verbatim}
SELECT ...
FROM ...

INTERSECT

SELECT ...
FROM ...
\end{verbatim}
\noindent Il risultato contiene solamente le tuple che compaiono
\textbf{nel risultato di entrambe le SELECT}.
In termini insiemistici, se la prima query produce l'insieme $A$
e la seconda produce l'insieme $B$, allora:
\[
A \ \texttt{INTERSECT} \ B = A \cap B
\]
A differenza della differenza, l'intersezione è commutativa:
\[
A \cap B = B \cap A
\]
\textcolor{verdeEsempio}{Esempio} 
Consideriamo la query:
\begin{verbatim}
SELECT nome
FROM impiegato
INTERSECT
SELECT cognome AS nome
FROM impiegato;
\end{verbatim}
\noindent La prima query:
\begin{verbatim}
SELECT nome
FROM impiegato
\end{verbatim}
\noindent restituisce tutti i \textbf{nomi degli impiegati}.\\
La seconda query:
\begin{verbatim}
SELECT cognome AS nome
FROM impiegato
\end{verbatim}
\noindent restituisce tutti i \textbf{cognomi degli impiegati}.
L'intersezione restituisce quindi:
\[
\boxed{
\text{valori che compaiono sia come nome sia come cognome}
}
\]
\textcolor{verdeEsempio}{Esempio} supponiamo che:
\[
A =
\{\text{Mario},\text{Luca},\text{Rossi},\text{Anna}\}
\]
sia l'insieme dei nomi e che:
\[
B =
\{\text{Rossi},\text{Bianchi},\text{Luca},\text{Verdi}\}
\]
sia l'insieme dei cognomi.
Allora:
\[
A \cap B =
\{\text{Luca},\text{Rossi}\}
\]
perché \texttt{Luca} e \texttt{Rossi} compaiono sia tra i nomi
sia tra i cognomi.
\textbf{Compatibilità tra le due SELECT}
Come per \texttt{UNION} ed \texttt{EXCEPT}, le due \texttt{SELECT}
devono restituire lo \textbf{stesso numero di colonne} e le colonne
nelle stesse posizioni devono avere tipi compatibili.
In questo caso:
\[
\begin{array}{ccc}
\text{\texttt{nome}} & \longleftrightarrow &
\text{\texttt{cognome}}
\end{array}
\]
L'alias:
\begin{verbatim}
cognome AS nome
\end{verbatim}
rinomina la colonna \texttt{cognome} in \texttt{nome}.
L'alias rende più chiaro il risultato, ma non è necessario
per poter eseguire \texttt{INTERSECT}.\\
\textbf{Equivalenza con un self join} la stessa interrogazione può essere espressa
anche senza utilizzare \texttt{INTERSECT}:
\begin{verbatim}
SELECT DISTINCT i.nome
FROM impiegato i, impiegato j
WHERE i.nome = j.cognome;
\end{verbatim}
\noindent In questo caso la tabella \texttt{impiegato} viene considerata
\textbf{due volte}:
\[
\texttt{impiegato i}
\qquad\text{e}\qquad
\texttt{impiegato j}
\]
Gli alias \texttt{i} e \texttt{j} rappresentano due copie logiche
della stessa tabella.
La condizione:
\begin{verbatim}
i.nome = j.cognome
\end{verbatim}
\noindent cerca tutte le situazioni in cui il nome di un impiegato coincide
con il cognome di un altro impiegato
che è esattamente ciò che cercava la query con \texttt{INTERSECT}.\\
La parola \texttt{DISTINCT} è importante perché il join potrebbe
produrre più volte lo stesso nome. Poiché \texttt{INTERSECT}
elimina normalmente i duplicati, utilizziamo \texttt{DISTINCT}
per ottenere lo stesso comportamento.
\subsubsection*{\texttt{INTERSECT} e \texttt{INTERSECT ALL}}
Normalmente:
\[
\boxed{
\texttt{INTERSECT}
\quad\Rightarrow\quad
\text{elimina i duplicati}
}
\]
Con:
\[
\boxed{
\texttt{INTERSECT ALL}
\quad\Rightarrow\quad
\text{mantiene le molteplicità}
}
\]
Ad esempio, supponiamo che:
\[
A = \{a,a,a,b\}
\]
e:
\[
B = \{a,a,c\}
\]
Con \texttt{INTERSECT} otteniamo:
\[
A \ \texttt{INTERSECT} \ B = \{a\}
\]
perché i duplicati vengono eliminati.
Con \texttt{INTERSECT ALL}, invece:
\[
A \ \texttt{INTERSECT ALL} \ B = \{a,a\}
\]
perché $a$ compare tre volte in $A$ e due volte in $B$.
Il numero di copie mantenute nell'intersezione è il minimo
tra le due molteplicità:
\[
\min(3,2)=2
\]

\section{Definizione dei dati in PostgreSQL}
In PostgreSQL è importante distinguere tra \textbf{database},
\textbf{schema} e \textbf{tabella}.\\
Un database viene creato con:
\begin{verbatim}
CREATE DATABASE nome_database;
\end{verbatim}
\noindent All'interno di uno stesso database possiamo creare diversi
\textbf{schema} mediante:
\begin{verbatim}
CREATE SCHEMA nome_schema;
\end{verbatim}
\noindent In PostgreSQL uno schema può essere visto come un \textbf{namespace},
cioè un contenitore utilizzato per organizzare gli oggetti del database,
come tabelle e vincoli.\\
La struttura può essere quindi vista come:
\[
\boxed{
\text{Database}
\supset
\text{Schema}
\supset
\text{Tabelle}
}
\]
Uno stesso database può quindi contenere più schema.

\subsection{Accesso agli oggetti di uno schema}
Per indicare esplicitamente un oggetto appartenente a uno schema si usa:
\[
\boxed{
\texttt{nomeSchema.nomeOggetto}
}
\]
Ad esempio, se la tabella \texttt{Impiegato} appartiene allo schema
\texttt{Azienda}, possiamo riferirci ad essa come:
\begin{verbatim}
Azienda.Impiegato
\end{verbatim}
\noindent È possibile eseguire operazioni che coinvolgono tabelle appartenenti
a schema diversi dello \textbf{stesso database}.\\
Invece, normalmente PostgreSQL non permette a una singola query di
accedere direttamente a tabelle appartenenti a database differenti.

\section{CREATE TABLE}
L'istruzione:
\begin{verbatim}
CREATE TABLE
\end{verbatim}
\noindent appartiene al \textbf{DDL} (\emph{Data Definition Language}) e serve
a definire una nuova tabella.\\
Con \texttt{CREATE TABLE} specifichiamo:
\begin{itemize}
    \item il nome della tabella;
    \item gli attributi;
    \item il tipo (dominio) di ogni attributo;
    \item eventuali vincoli.
\end{itemize}
\noindent Quando viene eseguito il comando viene creata inizialmente una
\textbf{tabella vuota} con la struttura specificata.
La sintassi generale è:
\begin{verbatim}
CREATE TABLE NomeTabella (
    Attributo1 Tipo [Vincoli],
    Attributo2 Tipo [Vincoli],
    ...
    AttributoN Tipo [Vincoli],
    [AltriVincoli]
);
\end{verbatim}
\noindent Quindi, in maniera schematica:
\[
\boxed{
\text{Attributo}
+
\text{Tipo}
+
\text{eventuali vincoli}
}
\]

% ---------------------------------------------------------

\subsubsection{Esempio di CREATE TABLE}
Consideriamo una tabella che rappresenta gli impiegati:
\begin{verbatim}
CREATE TABLE Impiegato (
    Matricola  CHARACTER(6)  PRIMARY KEY,
    Nome       CHARACTER(20) NOT NULL,
    Cognome    CHARACTER(20) NOT NULL,
    Dipart     CHARACTER(15),
    Stipendio  NUMERIC(9) DEFAULT 0,
    Citta      CHARACTER(15),

    FOREIGN KEY (Dipart)
        REFERENCES Dipartimento(NomeDip),

    UNIQUE (Cognome, Nome)
);
\end{verbatim}
\noindent Analizziamo le varie parti.

\subsection{PRIMARY KEY}
\begin{verbatim}
Matricola CHARACTER(6) PRIMARY KEY
\end{verbatim}
significa che \texttt{Matricola} è la \textbf{chiave primaria}.\\
Quindi:
\[
\boxed{
\texttt{Matricola} \text{ identifica univocamente ogni impiegato}
}
\]
Inoltre una chiave primaria non può contenere valori \texttt{NULL}.
\subsection{NOT NULL}
Il vincolo:
\begin{verbatim}
Nome CHARACTER(20) NOT NULL
\end{verbatim}
\noindent impone che l'attributo \texttt{Nome} abbia sempre un valore.\\
Quindi:
\[
\boxed{
\texttt{Nome} \neq \texttt{NULL}
}
\]
Lo stesso vale per \texttt{Cognome}.

\subsection{DEFAULT}
La dichiarazione:
\begin{verbatim}
Stipendio NUMERIC(9) DEFAULT 0
\end{verbatim}
\noindent stabilisce un valore predefinito.\\
Se durante un inserimento non viene specificato lo stipendio,
il sistema utilizza:
\[
\boxed{\texttt{Stipendio} = 0}
\]

\subsection{FOREIGN KEY}
Il vincolo:
\begin{verbatim}
FOREIGN KEY (Dipart)
    REFERENCES Dipartimento(NomeDip)
\end{verbatim}
\noindent stabilisce che \texttt{Dipart} è una \textbf{foreign key} che fa
riferimento all'attributo \texttt{NomeDip} della tabella
\texttt{Dipartimento}.\\
Quindi, per ogni valore non nullo di \texttt{Dipart}, deve esistere
un corrispondente valore di \texttt{NomeDip}:
\[
\boxed{
\texttt{Impiegato.Dipart}
\longrightarrow
\texttt{Dipartimento.NomeDip}
}
\]
Questo realizza un \textbf{vincolo di integrità referenziale}.

\subsection{UNIQUE}
Il vincolo:
\begin{verbatim}
UNIQUE (Cognome, Nome)
\end{verbatim}
\noindent impone che non possano esistere due tuple con la stessa
\textbf{combinazione} di cognome e nome.\\
Ad esempio, non possono comparire due volte:
\[
(\text{Rossi},\text{Mario}).
\]
È invece possibile avere:
\[
(\text{Rossi},\text{Mario})
\qquad\text{e}\qquad
(\text{Rossi},\text{Luca}),
\]
perché la coppia completa è diversa.

\section{Domini e tipi degli attributi}
Ogni attributo di una tabella deve avere un \textbf{tipo},
che stabilisce quali valori può contenere.\\
I principali tipi SQL sono i seguenti.

\subsection{Stringhe}
Per memorizzare testo possiamo utilizzare:
\begin{verbatim}
CHAR(n)
CHARACTER(n)
VARCHAR(n)
CHARACTER VARYING(n)
\end{verbatim}
\noindent La differenza principale è:
\[
\boxed{
\begin{array}{c|c}
\texttt{CHAR(n)} & \text{lunghezza fissa} \\
\texttt{VARCHAR(n)} & \text{lunghezza variabile}
\end{array}
}
\]
Ad esempio:
\begin{verbatim}
Nome VARCHAR(20)
\end{verbatim}
\noindent permette di memorizzare stringhe di lunghezza variabile fino al
limite specificato.

\subsection{Tipi numerici}
Per i numeri interi possiamo utilizzare, ad esempio:
\begin{verbatim}
INTEGER
SMALLINT
\end{verbatim}
\noindent Per valori numerici esatti:
\begin{verbatim}
NUMERIC(p,s)
DECIMAL(p,s)
\end{verbatim}
\noindent dove:
\begin{itemize}
    \item $p$ indica la \textbf{precisione}, cioè il numero totale di cifre;
    \item $s$ indica la \textbf{scala}, cioè il numero di cifre dopo
          la virgola.
\end{itemize}
\noindent Ad esempio:
\begin{verbatim}
NUMERIC(6,2)
\end{verbatim}
\noindent può rappresentare numeri con al massimo $6$ cifre complessive,
di cui $2$ dopo la virgola.\\
Per valori reali approssimati esistono inoltre tipi come:
\begin{verbatim}
REAL
DOUBLE PRECISION
FLOAT
\end{verbatim}

\subsection{Date e orari}
Per rappresentare informazioni temporali troviamo:
\begin{verbatim}
DATE
TIME
TIMESTAMP
\end{verbatim}
\noindent Inoltre esistono tipi che possono tenere conto del fuso orario,
come:
\begin{verbatim}
TIME WITH TIME ZONE
TIMESTAMP WITH TIME ZONE
\end{verbatim}

\subsection{Altri tipi}
SQL prevede anche altri domini, ad esempio:
\begin{verbatim}
BOOLEAN
BIT(n)
BIT VARYING(n)
\end{verbatim}
\noindent Il tipo \texttt{BOOLEAN} viene utilizzato per valori logici, mentre
\texttt{BIT} permette di rappresentare sequenze di bit.

\subsection{Select}
L'istruzione di interrogazione in SQL è \texttt{select} che definisce una interrogazione (query) e restituisce il risultato della valutazione di quella query sulla base di dati in forma di tabella. La sua forma elementare è:
\begin{verbatim}
    select  Attributo,...,Attributo
    from    Tabella
    where   Condizione
\end{verbatim}
\noindent semantica:\\
ogni tupla $t$ della Tabella è indicata nella clausola \underline{from} viene analizzata. Se $t$ non soddisfa la condizione nella clausola \underline{where}, allora viene ignorata. 
Altrimenti da $t$ viene prodotta la target list (lista attributi) secondo quanto specificato nella target list che appare dopo \underline{select} e la tupla risultante da tale target list viene inserita nel risultato. 
Il risultato della esecuzione della query viene restituito nel canale di output del sistema e volendo memorizzarlo nella base di dati.
La semantica descritta chiarisce che l'istruzione è analoga alla seguente espressione dell'algebra relazionale\\
$$PROJ_{Attributo,...,Attributo}(SEL_{Condizione}(Tabella))$$\\
Diciamo analoga e non equivalente perchè in sql la tabella può avere duplicati.\\

\section{Ridenominazione As}
"as" nella lista degli attributi serve a ridenominare gli attributi, specificando esplicitamente un nome per un attributo del risultato.\\
\textcolor{verdeEsempio}{Esempio:}
\begin{verbatim}
select nome as name, reddito as salary
from persone
where eta<30
\end{verbatim}
\noindent restituisce com risultato una tabella con due attributi, il primo nome name ed il secondo salary.\\
"as" serve anche ad assegnare un nuovo nome alle tabelle nel'ambito di una query.\\
\textcolor{verdeEsempio}{Esempio:}
\begin{verbatim}
select p.nome as name, p.reddito as salary
from persone as p
where p.eta<30
\end{verbatim}
\section{Distinct, $<$, *, where, null}
\subsection{Distinct}
Per non avere duplicati nella query nella select aggiungiamo distinct\\
\textcolor{verdeEsempio}{Esempio:}\\
\texttt{select distinct attributo1,...,attributo2 from tabella1}
\subsection{$<$}
La utilizziamo per evitare ridondanze quando stiamo confrontando righe della stessa tabella tra loro, tipicamente in un self join, e vogliamo ottenere ogni coppia una sola volta.\\
\textcolor{verdeEsempio}{Esempio:}
\begin{verbatim}
    select p1.nome, p2.nome
    from persona p1, persona p2
    where p1.id < p2.id
\end{verbatim}
\subsection{*}
Qunado vogliamo che una query restituisca tutti gli attributi usiamo '*' nella select al posto della lista degli attributi.\\
\textcolor{verdeEsempio}{Esempio:}\\
Data una tabella R sugli attributi A1,...,An:\medskip\\
\begin{minipage}[c]{0.40\textwidth}
       \begin{verbatim}
        select *
        from tabella1
        where condizione
        \end{verbatim}
    \end{minipage}
    equivale a
    \begin{minipage}[c]{0.25\textwidth}
        \begin{verbatim}
            select A1,...,An
            from R
            where condizione
        \end{verbatim}
\end{minipage}
\subsection{Condizione while}
Quando eseguiamo una query in cui non c'è una condizione possiamo scrivere while true o non scrivere proprio where.\\
\textcolor{verdeEsempio}{Esempio:}\\
\begin{minipage}[c]{0.40\textwidth}
       \begin{verbatim}
        select A1,...,An
        from tabella1
        \end{verbatim}
    \end{minipage}
    equivale a
    \begin{minipage}[c]{0.25\textwidth}
        \begin{verbatim}
            select A1,...,An
            from R
            where true
        \end{verbatim}
\end{minipage}\medskip\\
Nella clausola where possono comparire espressioni booleane qualunque\\
\textcolor{verdeEsempio}{Esempio:}\\
\texttt{select *
from persone
where reddito > 25 and (eta < 30 or eta >60)}\\
Nelle condizioni nella clausola where si possono usare molti operatori che SQL mette a disposizione.\\
Ad esempio l'operatore \texttt{like} che consente di verificare che una stringa appartenga al linguaggio definito da una espressione regolare.\\
\textcolor{verdeEsempio}{Esempio:}\\
se vogliamo conoscere quali sono le persone che hanno un nome che inizia per 'A', ha 'd' come terza lettera e può continuare con altri caratteri.
\begin{verbatim}
select *
from persone
where nome like 'A_d%'
\end{verbatim}
\subsection{gestione dei valori nulli - "is null" e "is not null"}
nelle condizioni che compaiono nella clausola where si possono usare anche i predicati "is null" e "is not null" per gestire i valori nulli\\
\textcolor{verdeEsempio}{Esempio:}\\
vogliamo le persone la cui eta è o ptrebbe essere maggiore di 40
\begin{verbatim}
select *
from persone
where eta > 40 or eta is null    
\end{verbatim}
\section{Espressioni nella target list}

\textcolor{verdeEsempio}{Esempio:}\\
\texttt{select 'Gigi' as nomePersona, eta, reddito/2 as redditoSemestrale\\

Espressione costituita da una costante di tipo stringa che aggiunge un attributo nomePersona con la stringa 'Gigi'\\

\section{Selezione, proiezione e join}
le istruzioni select che abbiamo visto finora hanno una sola tabella nella clausola from e quindi permettono di realizzare:
\begin{itemize}
    \item selezioni
    \item proiezioni
    \item ridenominazioni
\end{itemize}
\noindent I joni si possono realizzare indicando due o più tabelle nella clausola from, separate da virgola
\subsection{Select}
\subsubsection{sintassi e semantica}
La forma base delle selct in SQL è:
\begin{verbatim}
    select <target list>  --> lista attributi
    from R1,R2,...,Rn
    where <condizione>
\end{verbatim}
\noindent In algebra relazionale: $PROJ_{target list}(SEL_{<condizione>}(R_1 \times R_2 \times ... \times R_n))$\\
Ogni tupla t del prodotto cartesiano viene analizzata. Se t non verifica la condizione della clausola WHERE, essa viene ignorata. Se invece t verifica la condizione della clausola 
WHERE, allora da t viene prodotta la target list secondo la proiezione specificata nella clausola SELECT e la tupla risultante da tale target list viene inserita nel risultato\\
\underline{Attenzione}: questo non significa che il DBMS calcola il prodotto cartesiano di R1,R2,..,Rn. Significa che ilrisultato ottenuto è lo stesso di quello che si ottiene partendo dal prodotto cartesiano.
\subsection{Join}
Date due relazioni: R1(A1, A2) e R2(A3, A4)
\begin{verbatim}
    select R1.A1, R2.A4
    from R1, R2
    where R1.A2 = R2.A3
\end{verbatim}
\noindent è analoga a: $PROJ_{A1,A4}(R1 \text{ }JOIN_{A2=A3}\text{ }R2)$\\
Possono essere necessarie ridenominazioni:
\begin{itemize}
    \item nella target list
    \item nella clausola from (in particolare, introdurre alias consente di riferirsi due o più volte alla stessa tabella)
\end{itemize}
\noindent \textcolor{verdeEsempio}{Esempio:}
\begin{verbatim}
    select X.A1 as B1,...
    from R1 as X, R2 as Y, R1 as Z
    where X.A2 = Y.A3 and Y.A4 = Z.A1
\end{verbatim}
\noindent Si può anche scireve senza 'as'.\medskip\\
Date le tabelle R1(A1, A2) e R2(A3, A4)
\begin{verbatim}
    select distinct X.A1 as B1, Y.A4 as B2
    from R1 as X, R2 as Y, R1 as Z
    where X.A2 = Y.A3 and Y.A4 = Z.A1 
\end{verbatim}
\noindent è equivalente a:
$REN_{B1,B2 \leftarrow A1,A4}( PROJ_{A1,A4} (SEL_{A2=A3 \text{ and }A4=C1 }( R1 \text{ }JOIN\text{ }R2\text{ }JOIN\text{ }REN_{C1,C2 \leftarrow A1,A2}(R1))))$
\subsection{Self-join}
Il self-join è un join in cui la stessa relazione compare sia come operando sinistro sia come operando destro ed è cruciale quando dobbiamo combinare due tuple della stessa relazione.\\
\textcolor{verdeEsempio}{Esempio:}\\
\texttt{persone(nome, eta, reddito)}\\
\underline{query}: Vogliamo le coppie di persone con lo stesso reddito\\
\underline{soluzione}:
\begin{verbatim}
    select p1.nome, p1.eta, p1.reddito, p2.nome, p2.eta
    from persone p1, persone p2
    where p1.reddito=p2.reddito and p1.nome<p2.nome
\end{verbatim}
\noindent utilizziamo p1.nome $<$ p2.nome per eliminare le tuple ridondanti, in quando lascia solo le tuple in cui p1.nome viene prima in ordine alfabetico di p2.nome

\subsection{Join multipli}

Quando una query richiede di mettere in relazione informazioni provenienti da più tabelle, è possibile eseguire \textbf{più join nella stessa interrogazione}. L'idea è costruire progressivamente il risultato: ogni join collega una nuova tabella al risultato ottenuto dai join precedenti attraverso una specifica condizione.
Un primo esempio riguarda la ricerca del \textbf{padre e della madre di ogni persona della quale entrambi i genitori sono noti}. Le tabelle \texttt{paternita} e \texttt{maternita} possiedono entrambe l'attributo \texttt{figlio}, che permette di collegare le informazioni relative alla stessa persona:

\begin{verbatim}
select paternita.figlio, padre, madre
from maternita, paternita
where paternita.figlio = maternita.figlio
\end{verbatim}

\noindent In questo caso è sufficiente un solo join. Se, però, si vuole anche garantire che il figlio compaia effettivamente nella tabella \texttt{persone}, è necessario introdurre un \textbf{secondo join}:

\begin{verbatim}
select paternita.figlio, padre, madre
from maternita, paternita, persone
where paternita.figlio = maternita.figlio
  and paternita.figlio = persone.nome
\end{verbatim}

\noindent Quindi, quando sono presenti più join, nella clausola \texttt{from} vengono indicate tutte le tabelle coinvolte, mentre nella clausola \texttt{where} vengono specificate le condizioni che stabiliscono come collegarle tra loro. Ogni condizione di join permette di associare tuple che rappresentano entità correlate. 
Un caso più articolato si presenta quando la \textbf{stessa tabella deve essere utilizzata più volte con ruoli differenti}. L'esempio considerato è quello delle persone che guadagnano più dei rispettivi padri, mostrando il nome della persona, il suo reddito e il reddito del padre.
La tabella \texttt{persone} deve comparire due volte: una volta per rappresentare il \textbf{padre} e una volta per rappresentare il \textbf{figlio}. Per distinguere le due occorrenze si utilizzano degli \textbf{alias}:

\begin{verbatim}
select f.nome, f.reddito as reddito,
       p.reddito as redditoPadre
from persone p, paternita t, persone f
where p.nome = t.padre
  and t.figlio = f.nome
  and f.reddito > p.reddito
\end{verbatim}

\noindent Gli alias hanno quindi un ruolo fondamentale:
\begin{itemize}
    \item \texttt{p} rappresenta la persona nel ruolo di \textbf{padre};
    \item \texttt{t} rappresenta la tabella \texttt{paternita};
    \item \texttt{f} rappresenta la persona nel ruolo di \textbf{figlio}.
\end{itemize}

\noindent I join vengono concettualmente costruiti in più passaggi. Prima si collega \texttt{paternita} alla copia di \texttt{persone} che rappresenta il figlio, mediante la corrispondenza

\[
\texttt{t.figlio = f.nome}.
\]

\noindent In questo modo si ottengono insieme le informazioni sulla relazione di paternità e quelle relative al figlio. Successivamente si collega anche la copia di \texttt{persone} che rappresenta il padre:

\[
\texttt{p.nome = t.padre}.
\]

\noindent A questo punto ogni tupla contiene le informazioni necessarie sia sul figlio sia sul relativo padre. È quindi possibile applicare la condizione

\[
\texttt{f.reddito > p.reddito},
\]

\noindent che mantiene solamente i casi in cui il reddito del figlio è maggiore di quello del padre. Infine, con la \texttt{select} vengono mantenuti solamente gli attributi richiesti: nome del figlio, reddito del figlio e reddito del padre.
In generale, quindi, una query con \textbf{più join} può essere vista come una costruzione progressiva: si collegano prima due tabelle, il risultato viene poi collegato a un'altra tabella e così via. Se una stessa tabella deve rappresentare entità con ruoli differenti, la si inserisce più volte nella query assegnandole alias diversi. Le condizioni nella clausola \texttt{where} stabiliscono sia i collegamenti tra le varie occorrenze delle tabelle sia gli eventuali ulteriori criteri di selezione.

\subsection{Join esplicito}
\begin{verbatim}
select ...
from Tabella1 join Tabella2 on CondJoin,...
[where AltraCondizione]
\end{verbatim}

\noindent La parola chiave \texttt{join} specifica le tabelle da combinare, mentre la clausola \texttt{on} contiene la \textbf{condizione di join}, cioè la condizione che stabilisce quali tuple delle due tabelle devono essere associate. La clausola \texttt{where}, invece, può essere utilizzata per imporre ulteriori condizioni sul risultato del join.\\
\textcolor{verdeEsempio}{Esempio} per ottenere padre e madre delle persone per le quali entrambi i genitori sono noti, invece di scrivere:
\begin{verbatim}
select paternita.figlio, padre, madre
from maternita, paternita
where paternita.figlio = maternita.figlio
\end{verbatim}
\noindent si può utilizzare il join esplicito:
\begin{verbatim}
select madre, paternita.figlio, padre
from maternita join paternita on
     paternita.figlio = maternita.figlio
\end{verbatim}
\noindent In questo caso si tratta di un \textbf{equi-join}, perché la condizione specificata dopo \texttt{on} è un'uguaglianza.
Il join esplicito può essere applicato \textbf{più volte consecutivamente}. Il risultato di un primo join è infatti una nuova tabella, che può essere utilizzata come operando di un secondo join.\\ 
\textcolor{verdeEsempio}{Esempio:}
\begin{verbatim}
select f.nome, f.reddito, p.reddito
from persone p
     join paternita t on p.nome = t.padre
     join persone f on t.figlio = f.nome
where f.reddito > p.reddito
\end{verbatim}
\noindent Il primo join:
\begin{verbatim}
persone p join paternita t on p.nome = t.padre
\end{verbatim}
\noindent collega ogni padre alla relativa informazione nella tabella \texttt{paternita}. Il risultato viene poi utilizzato nel secondo join:
\begin{verbatim}
join persone f on t.figlio = f.nome
\end{verbatim}
\noindent che associa anche le informazioni relative al figlio. Solo dopo aver costruito questi collegamenti viene applicata la condizione:
\begin{verbatim}
where f.reddito > p.reddito
\end{verbatim}
\noindent per mantenere i figli che guadagnano più del rispettivo padre.
È importante osservare che il \textbf{risultato di un join contiene gli attributi di entrambi gli operandi}. Di conseguenza, se si eseguono più join consecutivi, ogni risultato intermedio accumula gli attributi delle tabelle coinvolte.
Nella query sopra, il primo join esplicito nella clausola fromdà come risultato
una tabella con gli attributi: \texttt{p.nome, p.eta, p.reddito, t.padre. t.figlio}. Questa
tabella va in input al secondo join esplicito il cui risultato avrà come attributi:
\texttt{p.nome, p.eta, p.reddito, t.padre. t.figlio, f.nome, f.eta, ed f.reddito}.\\
In sintesi, il join esplicito permette di separare chiaramente le \textbf{condizioni che servono a collegare le tabelle}, scritte nella clausola \texttt{on}, dalle \textbf{condizioni che servono a filtrare il risultato}, che possono essere scritte nella clausola \texttt{where}. Inoltre, più join possono essere concatenati, utilizzando ogni risultato intermedio come operando del join successivo.
\subsection{Ridenominazione del risultato di un join esplicito}
Poiché il risultato di un join esplicito è una \textbf{tabella}, esso può essere utilizzato direttamente nella clausola \texttt{from} e può anche essere \textbf{ridenominato assegnandogli un alias}.
Riprendiamo l'esempio precedente. Il primo join era:
\begin{verbatim}
persone p join paternita t on p.nome = t.padre
\end{verbatim}
\noindent Questo join produce una tabella contenente gli attributi di entrambi gli operandi:
\[
p.nome,\ p.eta,\ p.reddito,\ t.padre,\ t.figlio.
\]
\noindent È possibile assegnare un alias, ad esempio \texttt{J}, all'intero risultato del join:
\begin{verbatim}
from (persone p join paternita t on p.nome = t.padre) as J,
     persone f
\end{verbatim}
\noindent Quando si assegna un alias a un join esplicito è necessario \textbf{racchiudere tra parentesi l'intera espressione di join}.
Un aspetto importante è la \textbf{visibilità degli alias}. Gli alias \texttt{p} e \texttt{t}, definiti all'interno delle parentesi, non sono più
referenziabili all'esterno. All'esterno delle parentesi è visibile solamente l'alias \texttt{J}.
Di conseguenza, invece di riferirsi agli attributi attraverso \texttt{p} e \texttt{t}, bisogna utilizzare \texttt{J}.\\ 
\textcolor{verdeEsempio}{Esempio:}
\begin{verbatim}
where f.reddito > J.reddito
  and f.nome = J.figlio
\end{verbatim}
\noindent In questo caso:
\[
\texttt{J.reddito}
\]

\noindent indica l'attributo \texttt{reddito} proveniente dalla tabella \texttt{persone p}, mentre
\[
\texttt{J.figlio}
\]

\noindent indica l'attributo \texttt{figlio} proveniente dalla tabella \texttt{paternita t}. La query può quindi essere scritta come:
\begin{verbatim}
select f.nome, f.reddito, J.reddito
from (persone p join paternita t on p.nome = t.padre) as J,
     persone f
where f.reddito > J.reddito
  and f.nome = J.figlio
\end{verbatim}
\noindent L'alias \texttt{J} deve quindi essere visto come il \textbf{nome della nuova tabella prodotta dal join}, che eredita gli attributi delle tabelle utilizzate
per costruirla.

\subsection{Ridenominazione degli attributi del risultato}
Quando la struttura dei join diventa più complessa, assegnare soltanto un nome
al risultato può non essere sufficiente. SQL permette quindi di specificare,
oltre al nome della nuova tabella, anche i \textbf{nomi dei suoi attributi}.\medskip\\
Ricordando che il database è così composto:
\begin{verbatim}
persone(nome, eta, reddito): contiene le informazioni sulle persone.
paternita(padre, figlio): rappresenta le relazioni padre-figlio.
maternita(madre, figlio): rappresenta le relazioni madre-figlio.
\end{verbatim}
\noindent Supponiamo ora di volere le coppie (senza ridondanze) di persone diverse
che hanno la stessa età e sono figli dello stesso padre.
Vogliamo utilizzare un join tra due join espliciti, uno per individuare le coppie
di persone diverse con la stessa eta (alias F) e l’altro per individuare le
coppie di tuple di paternita con lo stesso valore per “figlio".
Consideriamo un join tra due occorrenze della tabella \texttt{persone}:
\begin{verbatim}
persone r join persone s
on r.eta = s.eta and r.nome < s.nome
\end{verbatim}

\noindent Il risultato possiede sei attributi, cioè i tre attributi di \texttt{r} seguiti
dai tre attributi di \texttt{s}. Possiamo ridenominare l'intero risultato e,
contemporaneamente, i suoi attributi:
\begin{verbatim}
(persone r join persone s
 on r.eta = s.eta and r.nome < s.nome)
as F(n1,e1,r1,n2,e2,r2)
\end{verbatim}

\noindent L'alias non è quindi più soltanto \texttt{F}, ma specifica anche lo schema
della tabella risultante:
\[
F(n1,e1,r1,n2,e2,r2).
\]

\noindent I nomi vengono assegnati agli attributi rispettando il loro ordine. Quindi,
ad esempio, il primo attributo \texttt{r.nome} diventa \texttt{F.n1}, mentre
\texttt{s.nome} diventa \texttt{F.n2}.
Lo stesso meccanismo può essere applicato a un altro join:
\begin{verbatim}
(paternita p join paternita t on p.padre = t.padre)
as S(p1,f1,p2,f2)
\end{verbatim}

\noindent A questo punto i risultati dei due join possiedono attributi con nomi
esplicitamente definiti e possono essere a loro volta messi in join:
\begin{verbatim}
select F.n1, F.n2
from (persone r join persone s
      on r.eta = s.eta and r.nome < s.nome)
     as F(n1,e1,r1,n2,e2,r2)
join
     (paternita p join paternita t
      on p.padre = t.padre)
     as S(p1,f1,p2,f2)
on F.n1 = S.f1 and F.n2 = S.f2
\end{verbatim}

\noindent La ridenominazione degli attributi permette quindi di utilizzare senza ambiguità gli attributi dei \textbf{risultati intermedi dei join}, anche
quando si costruisce un join tra risultati di altri join espliciti.

\subsection{Natural Join}
SQL mette a disposizione il \textbf{natural join}, che permette di effettuare
automaticamente un equi-join utilizzando gli attributi che le due tabelle
hanno in comune, cioè gli attributi con lo stesso nome semplice.\\
\textcolor{verdeEsempio}{Esempio:} considerando le tabelle \texttt{maternita} e \texttt{paternita},
entrambe possiedono l'attributo \texttt{figlio}.\\ Con il join esplicito si
scriverebbe:
\begin{verbatim}
select paternita.figlio, padre, madre
from maternita join paternita on
     paternita.figlio = maternita.figlio
\end{verbatim}
\noindent Utilizzando il \textbf{natural join}, invece, non è necessario specificare
esplicitamente la condizione di join:
\begin{verbatim}
select paternita.figlio, padre, madre
from maternita natural join paternita
\end{verbatim}
\noindent SQL riconosce automaticamente che \texttt{figlio} è un attributo comune alle
due tabelle e utilizza la condizione:
\[
\texttt{paternita.figlio = maternita.figlio}.
\]
Il \texttt{natural join} può quindi essere visto come un \textbf{equi-join
automatico su tutti gli attributi che hanno lo stesso nome semplice} nelle
due tabelle.
Per \textbf{nome semplice} si intende il nome dell'attributo senza considerare
il nome della relazione o dello schema. 

\subsection{Prodotto cartesiano in SQL}
In algebra e in sql il join naturale tra due relazioni che non hanno attributi in comune corrisponde al prodotto cartesiano.\\
Per calcolare il prodotto cartesiano di due relazioni in SQL ci sono anche altre possibilità:
\begin{itemize}
    \item esprimendo il prodotto cartesiano in modo implicito, mettendo le due relazioni nella lista dopo la clausola from
    \item esprimendo il prodotto cartesiano in modo esplicito, usando l'operatore di nome \texttt{cross join} nella clausola from
\end{itemize}
\textcolor{verdeEsempio}{Esempio:}\\
Vogliamo il prodotto cartesiano della tabella paternita e della tabella persona
\begin{itemize}
    \item Soluzione con il join naturale (visto che le due tabelle non hanno attributi in comune): \begin{verbatim}
        select * from paternita natural join persona        
    \end{verbatim}
    \item Soluzione con il prodotto cartesiano implicito (lista nella form): \begin{verbatim}
        select * from paternita, perosna
    \end{verbatim}
    \item Soluzione con il prodotto cartesiano esplicito (cross join): \begin{verbatim}
        select * from paternita cross join persona
    \end{verbatim}
\end{itemize}

\newpage \subsection{Join esterno}
Il \textbf{join naturale esterno (outer join)} estende con valori nulli le tuple che non si accoppiano nel join: 
tali tuple verrebbero tagliate fuori da un join normale ed invece appaiono nel join esterno, accoppiate con valori nulli\\
esistono tre versioni:
\begin{itemize}
    \item \textbf{join esterno sinistro}: mantiene tutte le tuple del primo operando, estendendole con valori nulli, se necessario
    \item \textbf{join esterno destro}: mantiene tutte le tuple del primo operando, estendendole con valori nulli, se necessario
    \item \textbf{join esterno completo}: mantiene tutte le tuple sia del primo operando e sia del secondo operando, estendendole con valori nulli, se necessario
\end{itemize}
\noindent \textcolor{verdeEsempio}{Esempio:}\\
Padre di ogni persona e, se nota, anche la madre:
\begin{verbatim}
    select paternita.figlio, padre, madre
    from paternita left join maternita
         on paternita.figlio = maternita.figlio 
\end{verbatim}
\noindent \textcolor{verdeEsempio}{Esempio} con join completo in cui non perdo alcun figlio:
\begin{verbatim}
    select paternita.figlio, padre, madre, maternita.figlio 
    from paternita full outer join maternita 
         on paternita.figlio = maternita.figlio
\end{verbatim}

\section{Ordinamento, aggregazione e operazioni sui risultati delle query}
\subsection{Ordinamento del risultato: order by}
La clausola \texttt{ORDER BY} permette di \textbf{ordinare le tuple del risultato} di una query in base al valore di uno o più attributi.
La sintassi è:
\begin{verbatim}
order by attributo1, attributo2, ...
\end{verbatim}
\noindent Se non viene specificato diversamente, l'ordinamento è \textbf{crescente}.\\
\textcolor{verdeEsempio}{Esempio} vogliamo ottenere il nome e il reddito delle persone con meno di
30 anni, ordinandole prima in base al reddito e, a parità di reddito, in base al nome:
\begin{verbatim}
select nome, reddito
from persone
where eta < 30
order by reddito, nome
\end{verbatim}
\noindent L'ordinamento viene applicato seguendo l'ordine degli attributi indicati nella
clausola \texttt{ORDER BY}

\subsection{Limite alla dimensione del risultato: limit}
Si può indicare un limite alla dimensione del risultato con la clausola \texttt{limit} in SQL, al fine di avere come risultato al massimo un prefissato numero di tuple\\
\textcolor{verdeEsempio}{Esempio:}
\begin{verbatim}
select nome, reddito
from persone
where eta < 30
order by nome
limit 2
\end{verbatim}
\noindent otterremo una tabella con solo 2 tuple.

\subsection{Operatori aggregati}
Nelle espressioni della target list possiamo avere anche espressioni che calcolano valori a partire da insiemi di tuple:\\
\texttt{conteggio, minimo, massimo, media, totale}\\
Sintassi: \texttt{Funzione ([distinct] EspressioneSuAttributi)}\medskip\\
Quando un operatore aggregato ALFA compare nella target list di una query del tipo:
\begin{verbatim}
select <... ALFA ...>
from R1, R2,...,Rn
where <condizione>
\end{verbatim}
\noindent L'operatore aggregato viene applicato a tutte le tuple del prodotto cartesiano che soddisfano la condizione della clausola \texttt{where} ed il risultato sarà una 
singola tupla che conterrà il valore risultante o i valori risultanti dall'applicazione dell'operatore\\
\textcolor{verdeEsempio}{Esempio:}
\begin{verbatim}
select count(*)
from Persone
where eta > 30
\end{verbatim}
\noindent Tale query esegue i seguenti passi:\\
\begin{itemize}
    \item viene calcolato il prodotto cartesiano delle tabelle nella clausola \texttt{from}
    \item vengono selezionate le tuple della tabella che soddisfano la condizione nella clausola \texttt{where}
    \item viene applicato l'operatore aggregato (in questo caso \texttt{count(*)}) su tutte le tuple selezionate: viene quindi restituita 
            una tabella con una sola colonna ed una sola riga che contiene il risultato dell'applicazione dell'operatore aggregato, cioè il numero di tuple selezionate.
\end{itemize}
\subsubsection{count}
Sintassi:\\
\begin{itemize}
    \item conta il numero di tuple: \begin{verbatim}
        count(*)
    \end{verbatim}
    \item conta i valori di un attributo: \begin{verbatim}
        count (Attributo)
    \end{verbatim}
    \item conta i valori distinti di un attributo: \begin{verbatim}
        count (distinct Attributo)
    \end{verbatim}
\end{itemize}
\noindent \textcolor{verdeEsempio}{Esempio:} Quanti figli ha Franco?\\
\begin{verbatim}
select count(*) as NumFigliDiFranco
from paternita
where padre='Franco'
\end{verbatim}
\begin{center}
\begin{minipage}{0.45\textwidth}
    \centering
    \begin{tabular}{|c|c|}
        \hline
        \textbf{padre} & \textbf{figlio} \\ \hline
        Sergio & Franco \\ \hline
        Luigi & Olga \\ \hline
        Luigi & Filippo \\ \hline
        Franco & Andrea \\ \hline
        Franco & Aldo \\ \hline
    \end{tabular}
\end{minipage}
\hfil
\begin{minipage}{0.45\textwidth}
    \centering
    \begin{tabular}{|c|}
        \hline
        \textbf{NumFigliDiFranco} \\ \hline
        2 \\ \hline
    \end{tabular}
\end{minipage}
\end{center}
\noindent Il count applicato su un attributo specifico conta solo tuple in cui quell'attributo ha valore diverso da \texttt{NULL}

\subsubsection{Altri operatori aggregati}
\texttt{sum, avg, max, min}\\
Ammettono come argomento un attributo o un espressione (ma non '*'), sum e avg sono argomenti numerici o di tempo, mentre max e min sono argomenti su cui è definito un ordinamento.\\
\textcolor{verdeEsempio}{Esempio:} media dei redditi dei figli di Franco
\begin{verbatim}
select avg(reddito)
from persone join paternita on nome = figlio
where padre = 'Franco'
\end{verbatim}

\noindent Le \textbf{funzioni aggregate}, come
\[
\texttt{MAX}, \quad \texttt{MIN}, \quad \texttt{AVG}, \quad
\texttt{SUM}, \quad \texttt{COUNT},
\]
considerano un insieme di tuple e producono un \textbf{singolo valore}.
\textcolor{verdeEsempio}{Esempio} consideriamo la seguente interrogazione:
\begin{verbatim}
SELECT nome, MAX(reddito)
FROM persone;
\end{verbatim}
Questa interrogazione presenta un problema.\\
L'attributo \texttt{nome} viene infatti valutato \textbf{per ogni
singola tupla} della tabella, mentre
\[
\texttt{MAX(reddito)}
\]
viene calcolato considerando \textbf{tutte le tuple} della tabella e
restituisce un solo valore.\\
\textcolor{verdeEsempio}{Esempio} supponiamo di avere:
\begin{center}
\begin{tabular}{|c|c|}
\hline
\textbf{nome} & \textbf{reddito} \\ \hline
Anna   & 2000 \\ \hline
Marco  & 3500 \\ \hline
Luca   & 2500 \\ \hline
\end{tabular}
\end{center}
Il massimo reddito è
\[
\texttt{MAX(reddito)} = 3500.
\]
Ma quale nome dovrebbe essere restituito?
\[
(\text{Anna},3500), \qquad
(\text{Marco},3500), \qquad
(\text{Luca},3500)?
\]
La query non specifica quale tupla debba fornire il valore di
\texttt{nome}. Per questo motivo la \textbf{target list non è
omogenea}.\\
\noindent
\colorbox{SALZO}{\parbox{\dimexpr\linewidth-2\fboxsep}{\begin{regola}
Se utilizziamo funzioni aggregate senza \texttt{GROUP BY}, gli
elementi della \texttt{SELECT} devono essere omogenei: non possiamo
mescolare attributi riferiti alle singole tuple con valori aggregati
calcolati sull'intera tabella.\end{regola}}}\\
\textcolor{verdeEsempio}{Esempio} la seguente interrogazione è corretta:
\begin{verbatim}
SELECT MIN(eta), AVG(reddito)
FROM persone;
\end{verbatim}
In questo caso entrambi gli elementi della target list sono funzioni
aggregate:
\[
\texttt{MIN(eta)}
\qquad\text{e}\qquad
\texttt{AVG(reddito)}.
\]
Entrambe considerano l'insieme delle tuple e restituiscono un singolo
valore. La target list è quindi \textbf{omogenea}.

\subsection{group by}
Nei casi visti in precedenza, gli operatori aggregati sono applicati all'insieme di tutte le tuple che formano il risultato di una query.
In molti casi, vorremmo che le funzioni di aggregazione venissero applicate a \underline{gruppi di tuple} delle relazioni. Per specificare i gruppi di tuple su cui applicare le funzioni, si utilizza la clausola \texttt{group by}:
\begin{verbatim}group by listaAttributi\end{verbatim}

\noindent \textcolor{verdeEsempio}{Esempio} Supponiamo di avere la seguente tabella:

\begin{center}
\begin{tabular}{|c|c|c|}
\hline
\textbf{nome} & \textbf{dipartimento} & \textbf{reddito} \\ \hline
Anna  & Informatica & 2000 \\ \hline
Luca  & Informatica & 3000 \\ \hline
Marco & Vendite     & 2500 \\ \hline
Sara  & Vendite     & 3500 \\ \hline
\end{tabular}
\end{center}
Vogliamo conoscere il reddito medio \textbf{di ogni dipartimento}.
Scriviamo:
\begin{verbatim}
SELECT dipartimento, AVG(reddito)
FROM persone
GROUP BY dipartimento;
\end{verbatim}
\noindent La clausola \texttt{GROUP BY dipartimento} divide le tuple in gruppi
in base al valore di \texttt{dipartimento}.
Si formano quindi due gruppi:
\[
G_1 =
\{
(\text{Anna},\text{Informatica},2000),
(\text{Luca},\text{Informatica},3000)
\}
\]
e
\[
G_2 =
\{
(\text{Marco},\text{Vendite},2500),
(\text{Sara},\text{Vendite},3500)
\}.
\]
A questo punto \texttt{AVG(reddito)} viene calcolato
\textbf{separatamente su ciascun gruppo}.
Per Informatica:
\[
\frac{2000+3000}{2}=2500
\]
Per Vendite:
\[
\frac{2500+3500}{2}=3000.
\]
Il risultato finale sarà:
\begin{center}
\begin{tabular}{|c|c|}
\hline
\textbf{dipartimento} & \textbf{AVG(reddito)} \\ \hline
Informatica & 2500 \\ \hline
Vendite & 3000 \\ \hline
\end{tabular}
\end{center}
Quindi possiamo ricordare che:
\[
\boxed{\text{GROUP BY crea i gruppi e le funzioni aggregate
vengono applicate a ciascun gruppo}}
\]
\noindent Semantica di una query con GROUP BY\\
Consideriamo una query della forma:
\begin{verbatim}
SELECT <target list>
FROM R1, ..., Rn
WHERE <condizione>
GROUP BY A;
\end{verbatim}
Per comprenderne il funzionamento possiamo immaginare l'esecuzione
in diversi passaggi.\\
\textbf{1. Selezione delle tuple}
Per prima cosa consideriamo la parte:
\begin{verbatim}
FROM R1, ..., Rn
WHERE <condizione>
\end{verbatim}
Concettualmente, in questa fase possiamo ignorare temporaneamente
sia la \texttt{SELECT} finale sia la \texttt{GROUP BY}.
Otteniamo quindi tutte le tuple che soddisfano la condizione
specificata nella clausola \texttt{WHERE}.\medskip\\
\textbf{2. Formazione dei gruppi}
Successivamente entra in gioco:
\begin{verbatim}
GROUP BY A
\end{verbatim}
Le tuple ottenute al passo precedente vengono divise in gruppi.
Due tuple appartengono allo stesso gruppo se hanno
\textbf{lo stesso valore dell'attributo $A$}.\\
\textcolor{verdeEsempio}{Esempio} se scriviamo:
\begin{verbatim}
GROUP BY dipartimento
\end{verbatim}
tutte le persone appartenenti a Informatica vengono messe nello
stesso gruppo, tutte quelle appartenenti a Vendite in un altro
gruppo, e così via.
Più in generale, se scriviamo:
\begin{verbatim}
GROUP BY A, B
\end{verbatim}
due tuple appartengono allo stesso gruppo solamente se hanno
\textbf{lo stesso valore sia di $A$ sia di $B$}.\medskip\\
\textbf{3. Applicazione delle funzioni aggregate}
Una volta creati i gruppi, le funzioni aggregate presenti nella
\texttt{SELECT} vengono calcolate
\textbf{separatamente all'interno di ciascun gruppo}.\\
\textcolor{verdeEsempio}{Esempio:}
\begin{verbatim}
SELECT dipartimento, MAX(reddito)
FROM persone
GROUP BY dipartimento;
\end{verbatim}
calcola
\[
\texttt{MAX(reddito)}
\]
non sull'intera tabella, ma separatamente per ogni dipartimento.\medskip\\
\textbf{4. Produzione del risultato}
In generale, viene prodotta \textbf{una tupla del risultato per ogni
gruppo}.
La differenza fondamentale è quindi:
\[
\begin{array}{ccl}
\text{senza GROUP BY}
&\Rightarrow&
\text{aggregazione sull'intero insieme di tuple}
\\[2mm]
\text{con GROUP BY}
&\Rightarrow&
\text{aggregazione separata per ogni gruppo}
\end{array}
\]
\subsubsection{Idea fondamentale}
La clausola \texttt{GROUP BY} non calcola direttamente una funzione
aggregata.
Il suo compito è \textbf{dividere le tuple in gruppi}.
Successivamente, funzioni come \texttt{AVG}, \texttt{MAX},
\texttt{MIN}, \texttt{SUM} e \texttt{COUNT} vengono applicate
separatamente alle tuple appartenenti a ciascun gruppo.\medskip\\
\colorbox{SALZO}{\parbox{\dimexpr\linewidth-2\fboxsep}{\begin{regola}
In una interrogazione che fa uso di \textbf{group by}, dovrebbero comparire solo target list "omogenee", ovvero target list che comprendono, oltre a funzioni di aggregazione, solamente attributi
che compaiono nella group by.\end{regola}}}\medskip\\
\textcolor{verdeEsempio}{Esempio:}\\
Redditi delle persone, raggrupati per età (\underline{non raggionevole}, perchè la target list è disomogenea: potrebbero esistere più valori di reddito per le persone appartenenti allo stesso gruppo):\\
\texttt{ select \textcolor{verdeScuro}{eta}, \textcolor{red}{reddito}\\
from persone\\
group by \textcolor{verdeScuro}{eta}}\\
Redditi delle persone, raggruppati per età (\underline{ragionevole}, perchè per ogni gruppo c'è una sola media dei redditi):\\
\texttt{select \textcolor{verdeScuro}{eta}, \textcolor{verdeScuro}{avg}(reddito)\\
from persone\\
group by \textcolor{verdeScuro}{eta}}

\subsection{Condizione sui gruppi: having}
Si possono anche imporre le condizioni di \textbf{selezione sui gruppi}. Per effettuare la selezione sui gruppi si usa la clausola \texttt{having}, che deve apparire dopo la \texttt{group by} e che di fatto 
opera un taglio sulle tuple del risultato dalla group by.\\
\textcolor{verdeEsempio}{Esempio:} i padri i cui figli hanno reddito medio maggiore di 25\\
Ricordando che il database è così composto:
\begin{verbatim}
persone(nome, eta, reddito): contiene le informazioni sulle persone.
paternita(padre, figlio): rappresenta le relazioni padre-figlio.
maternita(madre, figlio): rappresenta le relazioni madre-figlio.
\end{verbatim}
\begin{verbatim}
    select padre, avg(f.reddito)
    from persone f join paternita
         on figlio = f.nome
    group by padre
    having avg(f.reddito) > 25
\end{verbatim}
\noindent I padri i cui figli sotto i 30 anni hanno un reddito medio
maggiore di 20.\\
\begin{verbatim}
    select t.padre, avg(f.reddito)
    from persone f join paternita t
         on f.nome = t.figlio
    where f.eta < 30                ----> condizione sulle tuple che vanno a formare i gruppi
    group by t.padre
    having avg(f.reddito) > 20      ----> condizione sulle tuple che rappresentano i gruppi 
\end{verbatim}

\subsection{Riassunto e ordine}
L'ordine sintattico è:
\begin{verbatim}
    select ListaAttributiOEspressioni
    from ListaTabelle
    [where CondizioniSemplici]
    [group by ListaAttributiDiRaggruppamento]
    [having CondizioniAggregate]
    [order by ListaAttributiDiOrdinamento]
    [limit numero]
\end{verbatim}

\subsection{Unione}
la \texttt{select} da sola non permette di eseguire l'unione. Serve un costrutto esplicito:
\begin{verbatim}
    select ...
    union [all]
    select ...
\end{verbatim}
\noindent La target list delle due select devono avere lo stesso numero di elementi\\
Consideriamo la seguente query:
\begin{verbatim}
SELECT padre, figlio
FROM paternita
UNION
SELECT madre, figlio
FROM maternita;
\end{verbatim}
\noindent L'operatore \texttt{UNION} combina i risultati delle due \texttt{SELECT}.
L'associazione tra le colonne avviene \textbf{in base alla loro posizione}
e non in base al loro nome.
In particolare:
\[
\begin{array}{ccc}
\text{\texttt{padre}} & \longleftrightarrow & \text{\texttt{madre}} \\
\text{\texttt{figlio}} & \longleftrightarrow & \text{\texttt{figlio}}
\end{array}
\]
Quindi la prima colonna della prima \texttt{SELECT} viene unita con la
prima colonna della seconda \texttt{SELECT}, mentre la seconda colonna
viene unita con la seconda.
Affinché sia possibile utilizzare \texttt{UNION}, le due \texttt{SELECT}
devono restituire lo \textbf{stesso numero di colonne} e le colonne
corrispondenti devono avere \textbf{tipi compatibili}.
Poiché la prima query utilizza gli attributi \texttt{padre} e
\texttt{figlio}, mentre la seconda utilizza \texttt{madre} e
\texttt{figlio}, bisogna stabilire quali siano i nomi delle colonne
della relazione risultante.
Questo comportamento può dipendere dal DBMS. In molti sistemi vengono
utilizzati i nomi derivanti dalla prima \texttt{SELECT}. Il risultato
potrebbe quindi avere colonne:
\[
(\texttt{padre},\texttt{figlio})
\]
anche se nella prima colonna sono presenti sia padri sia madri.
Per rendere più chiaro il significato della colonna è possibile utilizzare
un alias:
\begin{verbatim}
SELECT padre AS genitore, figlio
FROM paternita
UNION
SELECT madre AS genitore, figlio
FROM maternita;
\end{verbatim}
\noindent ottenendo una relazione del tipo:
\[
(\texttt{genitore},\texttt{figlio})
\]
La prima \texttt{SELECT} produce le coppie padre--figlio, ad \textcolor{verdeEsempio}{esempio:}
\[
\begin{array}{c|c}
\textbf{padre} & \textbf{figlio} \\ \hline
\text{Sergio} & \text{Franco} \\
\text{Luigi} & \text{Olga} \\
\text{Luigi} & \text{Filippo} \\
\text{Franco} & \text{Andrea}
\end{array}
\]
La seconda \texttt{SELECT} produce invece le coppie madre--figlio, ad
\textcolor{verdeEsempio}{esempio:}
\[
\begin{array}{c|c}
\textbf{madre} & \textbf{figlio} \\ \hline
\text{Anna} & \text{Olga} \\
\text{Anna} & \text{Filippo} \\
\text{Maria} & \text{Andrea} \\
\text{Maria} & \text{Aldo}
\end{array}
\]
L'operatore \texttt{UNION} mette tutte queste tuple in un'unica relazione.
Se i nomi delle colonne vengono presi dalla prima \texttt{SELECT}, si può
ottenere:
\[
\begin{array}{c|c}
\textbf{padre} & \textbf{figlio} \\ \hline
\text{Sergio} & \text{Franco} \\
\text{Luigi} & \text{Olga} \\
\vdots & \vdots \\
\text{Anna} & \text{Olga} \\
\text{Anna} & \text{Filippo} \\
\text{Maria} & \text{Andrea} \\
\text{Maria} & \text{Aldo}
\end{array}
\]
Il fatto che \texttt{Anna} e \texttt{Maria} compaiano nella colonna
chiamata \texttt{padre} non significa che vengano considerate padri.
Il motivo è semplicemente che \texttt{UNION} opera in modo
\textbf{posizionale}:
\[
\boxed{
\text{prima  colonna} \leftrightarrow \text{prima colonna},
\qquad
\text{seconda colonna} \leftrightarrow \text{seconda colonna}
}
\]
Per questo motivo, dal punto di vista semantico, sarebbe più corretto
chiamare la prima colonna \texttt{genitore}.
\medskip
\noindent
\textbf{Nota:} \texttt{UNION} elimina eventuali righe duplicate.
Se si vogliono mantenere anche i duplicati bisogna utilizzare
\texttt{UNION ALL}.

\subsection{Differenza: EXCEPT}

L'operatore \texttt{EXCEPT} rappresenta la \textbf{differenza tra i risultati
di due query}.
La forma generale è:
\begin{verbatim}
SELECT ...
FROM ...
EXCEPT
SELECT ...
FROM ...
\end{verbatim}
\noindent Il risultato contiene le tuple prodotte dalla \textbf{prima SELECT} che
\textbf{non compaiono nel risultato della seconda SELECT}.
In termini insiemistici, se la prima query produce l'insieme $A$ e la
seconda produce l'insieme $B$, allora:
\[
A \ \texttt{EXCEPT} \ B = A \setminus B
\]
È importante osservare che la differenza \textbf{non è commutativa}:
\[
A \setminus B \neq B \setminus A
\]
\textcolor{verdeEsempio}{Esempio}
Consideriamo la query:
\begin{verbatim}
SELECT nome
FROM impiegato
EXCEPT
SELECT cognome AS nome
FROM impiegato;
\end{verbatim}
\noindent La prima query:
\begin{verbatim}
SELECT nome
FROM impiegato
\end{verbatim}
\noindent produce l'insieme dei \textbf{nomi degli impiegati}.\\
La seconda query:
\begin{verbatim}
SELECT cognome AS nome
FROM impiegato
\end{verbatim}
\noindent produce invece l'insieme dei \textbf{cognomi degli impiegati}.
Pertanto, l'intera query restituisce:
\[
\boxed{
\text{nomi degli impiegati che non compaiono anche come cognomi}
}
\]
Ad esempio, supponiamo di avere:
\[
A =
\{\text{Mario},\text{Luca},\text{Rossi},\text{Anna}\}
\]
come insieme dei nomi e:
\[
B =
\{\text{Rossi},\text{Bianchi},\text{Verdi}\}
\]
come insieme dei cognomi.
Allora:
\[
A \setminus B =
\{\text{Mario},\text{Luca},\text{Anna}\}
\]
poiché \texttt{Rossi} compare anche tra i cognomi e viene quindi escluso
dal risultato.\\
Come per \texttt{UNION}, le due \texttt{SELECT} devono avere lo
\textbf{stesso numero di colonne} e le colonne nelle stesse posizioni
devono avere tipi compatibili.
In questo esempio entrambe restituiscono una sola colonna:
\[
\begin{array}{ccc}
\text{\texttt{nome}} & \longleftrightarrow & \text{\texttt{cognome}}
\end{array}
\]
L'alias:
\begin{verbatim}
cognome AS nome
\end{verbatim}
\noindent rinomina la colonna \texttt{cognome} in \texttt{nome}. Tuttavia,
\textbf{non è l'alias a rendere possibile EXCEPT}: ciò che conta è che
le colonne corrispondenti siano compatibili.\\
\texttt{EXCEPT} e \texttt{EXCEPT ALL}\\
Normalmente:
\[
\boxed{\texttt{EXCEPT} \quad \Rightarrow \quad
\text{elimina i duplicati}}
\]
Quindi il risultato segue una semantica insiemistica.
Con:
\[
\boxed{\texttt{EXCEPT ALL} \quad \Rightarrow \quad
\text{tiene conto dei duplicati}}
\]
la differenza considera anche il numero di occorrenze delle tuple.
Ad esempio, se:
\[
A = \{a,a,a,b\}
\]
e:
\[
B = \{a\}
\]
allora con \texttt{EXCEPT} otteniamo:
\[
A \ \texttt{EXCEPT} \ B = \{b\}
\]
mentre con \texttt{EXCEPT ALL} otteniamo:
\[
A \ \texttt{EXCEPT ALL} \ B = \{a,a,b\}
\]
perché viene sottratta solamente una delle tre occorrenze di $a$.

\subsection{Intersezione: INTERSECT}
L'operatore \texttt{INTERSECT} permette di calcolare
l'\textbf{intersezione tra i risultati di due query}.\\
La forma generale è:
\begin{verbatim}
SELECT ...
FROM ...

INTERSECT

SELECT ...
FROM ...
\end{verbatim}
\noindent Il risultato contiene solamente le tuple che compaiono
\textbf{nel risultato di entrambe le SELECT}.
In termini insiemistici, se la prima query produce l'insieme $A$
e la seconda produce l'insieme $B$, allora:
\[
A \ \texttt{INTERSECT} \ B = A \cap B
\]
A differenza della differenza, l'intersezione è commutativa:
\[
A \cap B = B \cap A
\]
\textcolor{verdeEsempio}{Esempio} 
Consideriamo la query:
\begin{verbatim}
SELECT nome
FROM impiegato
INTERSECT
SELECT cognome AS nome
FROM impiegato;
\end{verbatim}
\noindent La prima query:
\begin{verbatim}
SELECT nome
FROM impiegato
\end{verbatim}
\noindent restituisce tutti i \textbf{nomi degli impiegati}.\\
La seconda query:
\begin{verbatim}
SELECT cognome AS nome
FROM impiegato
\end{verbatim}
\noindent restituisce tutti i \textbf{cognomi degli impiegati}.
L'intersezione restituisce quindi:
\[
\boxed{
\text{valori che compaiono sia come nome sia come cognome}
}
\]
\textcolor{verdeEsempio}{Esempio} supponiamo che:
\[
A =
\{\text{Mario},\text{Luca},\text{Rossi},\text{Anna}\}
\]
sia l'insieme dei nomi e che:
\[
B =
\{\text{Rossi},\text{Bianchi},\text{Luca},\text{Verdi}\}
\]
sia l'insieme dei cognomi.
Allora:
\[
A \cap B =
\{\text{Luca},\text{Rossi}\}
\]
perché \texttt{Luca} e \texttt{Rossi} compaiono sia tra i nomi
sia tra i cognomi.
\textbf{Compatibilità tra le due SELECT}
Come per \texttt{UNION} ed \texttt{EXCEPT}, le due \texttt{SELECT}
devono restituire lo \textbf{stesso numero di colonne} e le colonne
nelle stesse posizioni devono avere tipi compatibili.
In questo caso:
\[
\begin{array}{ccc}
\text{\texttt{nome}} & \longleftrightarrow &
\text{\texttt{cognome}}
\end{array}
\]
L'alias:
\begin{verbatim}
cognome AS nome
\end{verbatim}
rinomina la colonna \texttt{cognome} in \texttt{nome}.
L'alias rende più chiaro il risultato, ma non è necessario
per poter eseguire \texttt{INTERSECT}.\\
\textbf{Equivalenza con un self join} la stessa interrogazione può essere espressa
anche senza utilizzare \texttt{INTERSECT}:
\begin{verbatim}
SELECT DISTINCT i.nome
FROM impiegato i, impiegato j
WHERE i.nome = j.cognome;
\end{verbatim}
\noindent In questo caso la tabella \texttt{impiegato} viene considerata
\textbf{due volte}:
\[
\texttt{impiegato i}
\qquad\text{e}\qquad
\texttt{impiegato j}
\]
Gli alias \texttt{i} e \texttt{j} rappresentano due copie logiche
della stessa tabella.
La condizione:
\begin{verbatim}
i.nome = j.cognome
\end{verbatim}
\noindent cerca tutte le situazioni in cui il nome di un impiegato coincide
con il cognome di un altro impiegato
che è esattamente ciò che cercava la query con \texttt{INTERSECT}.\\
La parola \texttt{DISTINCT} è importante perché il join potrebbe
produrre più volte lo stesso nome. Poiché \texttt{INTERSECT}
elimina normalmente i duplicati, utilizziamo \texttt{DISTINCT}
per ottenere lo stesso comportamento.
\subsubsection*{\texttt{INTERSECT} e \texttt{INTERSECT ALL}}
Normalmente:
\[
\boxed{
\texttt{INTERSECT}
\quad\Rightarrow\quad
\text{elimina i duplicati}
}
\]
Con:
\[
\boxed{
\texttt{INTERSECT ALL}
\quad\Rightarrow\quad
\text{mantiene le molteplicità}
}
\]
Ad esempio, supponiamo che:
\[
A = \{a,a,a,b\}
\]
e:
\[
B = \{a,a,c\}
\]
Con \texttt{INTERSECT} otteniamo:
\[
A \ \texttt{INTERSECT} \ B = \{a\}
\]
perché i duplicati vengono eliminati.
Con \texttt{INTERSECT ALL}, invece:
\[
A \ \texttt{INTERSECT ALL} \ B = \{a,a\}
\]
perché $a$ compare tre volte in $A$ e due volte in $B$.
Il numero di copie mantenute nell'intersezione è il minimo
tra le due molteplicità:
\[
\min(3,2)=2
\]

\section{Definizione dei dati in PostgreSQL}
In PostgreSQL è importante distinguere tra \textbf{database},
\textbf{schema} e \textbf{tabella}.\\
Un database viene creato con:
\begin{verbatim}
CREATE DATABASE nome_database;
\end{verbatim}
\noindent All'interno di uno stesso database possiamo creare diversi
\textbf{schema} mediante:
\begin{verbatim}
CREATE SCHEMA nome_schema;
\end{verbatim}
\noindent In PostgreSQL uno schema può essere visto come un \textbf{namespace},
cioè un contenitore utilizzato per organizzare gli oggetti del database,
come tabelle e vincoli.\\
La struttura può essere quindi vista come:
\[
\boxed{
\text{Database}
\supset
\text{Schema}
\supset
\text{Tabelle}
}
\]
Uno stesso database può quindi contenere più schema.

\subsection{Accesso agli oggetti di uno schema}
Per indicare esplicitamente un oggetto appartenente a uno schema si usa:
\[
\boxed{
\texttt{nomeSchema.nomeOggetto}
}
\]
Ad esempio, se la tabella \texttt{Impiegato} appartiene allo schema
\texttt{Azienda}, possiamo riferirci ad essa come:
\begin{verbatim}
Azienda.Impiegato
\end{verbatim}
\noindent È possibile eseguire operazioni che coinvolgono tabelle appartenenti
a schema diversi dello \textbf{stesso database}.\\
Invece, normalmente PostgreSQL non permette a una singola query di
accedere direttamente a tabelle appartenenti a database differenti.

\section{CREATE TABLE}
L'istruzione:
\begin{verbatim}
CREATE TABLE
\end{verbatim}
\noindent appartiene al \textbf{DDL} (\emph{Data Definition Language}) e serve
a definire una nuova tabella.\\
Con \texttt{CREATE TABLE} specifichiamo:
\begin{itemize}
    \item il nome della tabella;
    \item gli attributi;
    \item il tipo (dominio) di ogni attributo;
    \item eventuali vincoli.
\end{itemize}
\noindent Quando viene eseguito il comando viene creata inizialmente una
\textbf{tabella vuota} con la struttura specificata.
La sintassi generale è:
\begin{verbatim}
CREATE TABLE NomeTabella (
    Attributo1 Tipo [Vincoli],
    Attributo2 Tipo [Vincoli],
    ...
    AttributoN Tipo [Vincoli],
    [AltriVincoli]
);
\end{verbatim}

% ---------------------------------------------------------

\subsubsection{Esempio di CREATE TABLE}
Consideriamo una tabella che rappresenta gli impiegati:
\begin{verbatim}
CREATE TABLE Impiegato (
    Matricola  CHARACTER(6)  PRIMARY KEY,
    Nome       CHARACTER(20) NOT NULL,
    Cognome    CHARACTER(20) NOT NULL,
    Dipart     CHARACTER(15),
    Stipendio  NUMERIC(9) DEFAULT 0,
    Citta      CHARACTER(15),

    FOREIGN KEY (Dipart)
        REFERENCES Dipartimento(NomeDip),

    UNIQUE (Cognome, Nome)
);
\end{verbatim}
\noindent Analizziamo le varie parti.

\subsection{PRIMARY KEY}
\begin{verbatim}
Matricola CHARACTER(6) PRIMARY KEY
\end{verbatim}
significa che \texttt{Matricola} è la \textbf{chiave primaria}.\\
Quindi:
\[
\boxed{
\texttt{Matricola} \text{ identifica univocamente ogni impiegato}
}
\]
Inoltre una chiave primaria non può contenere valori \texttt{NULL}.
\subsection{NOT NULL}
Il vincolo:
\begin{verbatim}
Nome CHARACTER(20) NOT NULL
\end{verbatim}
\noindent impone che l'attributo \texttt{Nome} abbia sempre un valore.\\
Quindi:
\[
\boxed{
\texttt{Nome} \neq \texttt{NULL}
}
\]
Lo stesso vale per \texttt{Cognome}.

\subsection{DEFAULT}
La dichiarazione:
\begin{verbatim}
Stipendio NUMERIC(9) DEFAULT 0
\end{verbatim}
\noindent stabilisce un valore predefinito.\\
Se durante un inserimento non viene specificato lo stipendio,
il sistema utilizza:
\[
\boxed{\texttt{Stipendio} = 0}
\]

\subsection{FOREIGN KEY}
Il vincolo:
\begin{verbatim}
FOREIGN KEY (Dipart)
    REFERENCES Dipartimento(NomeDip)
\end{verbatim}
\noindent stabilisce che \texttt{Dipart} è una \textbf{foreign key} che fa
riferimento all'attributo \texttt{NomeDip} della tabella
\texttt{Dipartimento}.\\
Quindi, per ogni valore non nullo di \texttt{Dipart}, deve esistere
un corrispondente valore di \texttt{NomeDip}:
\[
\boxed{
\texttt{Impiegato.Dipart}
\longrightarrow
\texttt{Dipartimento.NomeDip}
}
\]
Questo realizza un \textbf{vincolo di integrità referenziale}.

\subsection{UNIQUE}
Il vincolo:
\begin{verbatim}
UNIQUE (Cognome, Nome)
\end{verbatim}
\noindent impone che non possano esistere due tuple con la stessa
\textbf{combinazione} di cognome e nome.\\
Ad esempio, non possono comparire due volte:
\[
(\text{Rossi},\text{Mario}).
\]
È invece possibile avere:
\[
(\text{Rossi},\text{Mario})
\qquad\text{e}\qquad
(\text{Rossi},\text{Luca}),
\]
perché la coppia completa è diversa.

\section{Domini e tipi degli attributi}
Ogni attributo di una tabella deve avere un \textbf{tipo},
che stabilisce quali valori può contenere.\\
I principali tipi SQL sono i seguenti.

\subsection{Carattere}
Per memorizzare singoli caratteri o stringhe, anche di lunghezza variabile possiamo utilizzare:
\begin{verbatim}
CHAR(n) o CHARACTER(n)              - stringhe lunghezza fissa
VARCHAR(n) o CHARACTER VARYING(n)   - stringhe di lunghezza variabile
NCHAR(n) e NVARCHAR(n)              - come sopra ma UNICODE
\end{verbatim}
\noindent La differenza principale è:
\[
\boxed{
\begin{array}{c|c}
\texttt{CHAR(n)} & \text{lunghezza fissa} \\
\texttt{VARCHAR(n)} & \text{lunghezza variabile}
\end{array}
}
\]
Ad esempio:
\begin{verbatim}
Nome VARCHAR(20)
\end{verbatim}
\noindent permette di memorizzare stringhe di lunghezza variabile fino al
limite specificato.

\subsection{Tipi numerici}
\begin{verbatim}
INTEGER o SMALLINT  - interi
NUMERIC(p,s)        - valori numerici esatti
DECIMAL(p,s)        - valori numerici esatti anche negativi
REAL o FLOAT        - reali
\end{verbatim}
\noindent dove:
\begin{itemize}
    \item $p$ indica la \textbf{precisione}, cioè il numero totale di cifre;
    \item $s$ indica la \textbf{scala}, cioè il numero di cifre dopo
          la virgola.
\end{itemize}
\noindent Ad esempio:
\begin{verbatim}
NUMERIC(6,2)
\end{verbatim}
\noindent può rappresentare numeri con al massimo $6$ cifre complessive,
di cui $2$ dopo la virgola.

\subsection{Date e orari}
Per rappresentare informazioni temporali troviamo:
\begin{verbatim}
DATE
TIME
TIMESTAMP
\end{verbatim}
\noindent Inoltre esistono tipi che possono tenere conto del fuso orario,
come:
\begin{verbatim}
TIME WITH TIMEZONE
TIMESTAMP WITH TIMEZONE
\end{verbatim}

\subsection{Altri tipi}
SQL prevede anche altri domini, ad esempio:
\begin{verbatim}
BOOLEAN     - valore booleano V/F
BIT(n)      - singoli bit o stringhe di bit 
BIT VARYING(n)
\end{verbatim}
\noindent Il tipo \texttt{BOOLEAN} viene utilizzato per valori logici, mentre
\texttt{BIT} permette di rappresentare sequenze di bit.

\subsection{Modifiche degli schemi: alter table}
Permette di moficare una tabella\\
\textcolor{verdeEsempio}{Esempio: }\\
Sia il seguente database:\\
\texttt{Infrazioni(\underline{codice},data,vigile,prov,numero)}\\
\texttt{Vigili(\underline{matricola},cognome,nome)}\\
\texttt{Auto(\underline{prov},\underline{numero},cognome,nome)}
\begin{verbatim}
    create table Infrazioni(
        Codice CHARACTER(6) not null primary key,
        Data DATE not null,
        Vigile INTEGER not null references Vigili(Matricola),
        Provincia CHARACTER(2),
        Numero CHARACTER(6)
    )

    alter table Infrazioni
    add constraint MioVincolo foreign key(Provincia, Numero)
        references Auto(Provincia, Numero)
\end{verbatim}
\noindent Nella alter table si possono cambiare (\texttt{change, modify}) o eliminare (\texttt{drop}) elementi presenti o aggiungere nuovi elementi.\\
Il comando \texttt{ALTER TABLE} permette di modificare la struttura di una tabella già esistente, ad esempio aggiungendo vincoli di integrità referenziale.
È particolarmente utile quando due tabelle presentano \textbf{vincoli di integrità referenziale incrociati}, cioè quando ciascuna tabella contiene una chiave esterna che fa riferimento all'altra.
\subsection{Problema dei vincoli incrociati}
Consideriamo due tabelle $R_1$ e $R_2$ tali che:
\begin{itemize}
    \item $R_1$ contiene una chiave esterna verso $R_2$;
    \item $R_2$ contiene una chiave esterna verso $R_1$.
\end{itemize}
Non è possibile definire entrambe le tabelle direttamente con i rispettivi vincoli, poiché:
\begin{itemize}
    \item per creare $R_1$ con il vincolo, $R_2$ deve già esistere;
    \item per creare $R_2$ con il vincolo, $R_1$ deve già esistere.
\end{itemize}
Si genera quindi una \textbf{dipendenza circolare}.
\subsection{Soluzione mediante ALTER TABLE}
Il problema si risolve in tre passaggi:
\begin{enumerate}
    \item Si crea $R_1$ senza il vincolo di integrità referenziale verso $R_2$.
    \item Si crea $R_2$ includendo il vincolo verso $R_1$, che ora esiste.
    \item Si utilizza \texttt{ALTER TABLE} per aggiungere a $R_1$ il vincolo verso $R_2$.
\end{enumerate}
\subsection{Esempio: Persona e Città}
Consideriamo le relazioni:
\[
\text{Persona}(\underline{cf},cittaNascita)
\]
\[
\text{Citta}(\underline{nome},sindaco)
\]
con i seguenti vincoli:
\begin{itemize}
    \item \texttt{Persona.cittaNascita} fa riferimento a \texttt{Citta.nome};
    \item \texttt{Citta.sindaco} fa riferimento a \texttt{Persona.cf}.
\end{itemize}
Poiché i vincoli sono incrociati, procediamo in tre fasi.
\subsubsection*{1. Creazione della tabella Persona}
Si crea la tabella senza definire inizialmente la chiave esterna verso \texttt{Citta}.
\begin{verbatim}
CREATE TABLE Persona (
    cf VARCHAR(30) PRIMARY KEY,
    cittaNascita VARCHAR(30)
);
\end{verbatim}
\subsubsection*{2. Creazione della tabella Citta}
Ora è possibile definire il vincolo verso \texttt{Persona}, poiché quest'ultima esiste già.
\begin{verbatim}
CREATE TABLE Citta (
    nome VARCHAR(30) PRIMARY KEY,
    sindaco VARCHAR(30),
    CONSTRAINT vincolo1
        FOREIGN KEY (sindaco)
        REFERENCES Persona(cf)
);
\end{verbatim}
\subsubsection*{3. Aggiunta del vincolo mediante ALTER TABLE}
Una volta create entrambe le tabelle, si aggiunge il vincolo mancante su \texttt{Persona}.
\begin{verbatim}
ALTER TABLE Persona
ADD CONSTRAINT vincolo2
    FOREIGN KEY (cittaNascita)
    REFERENCES Citta(nome);
\end{verbatim}

\section{Manipolazione dei dati}
SQL permette di modificare il contenuto delle tabelle attraverso tre operazioni fondamentali:
\begin{itemize}
    \item \texttt{INSERT}: inserimento di una o più tuple.
    \item \texttt{DELETE}: eliminazione di una o più tuple.
    \item \texttt{UPDATE}: modifica dei valori di una o più tuple.
\end{itemize}
\noindent Le operazioni possono coinvolgere una o più tuple e possono essere eseguite sulla base di condizioni che fanno riferimento anche ad altre tabelle.
\subsection{Inserimento di tuple: INSERT}
Il comando \texttt{INSERT INTO} permette di inserire nuove tuple all'interno di una tabella.
Esistono due modalità principali di inserimento.
\subsubsection*{1. Inserimento mediante VALUES}
Permette di inserire tuple specificando direttamente i valori degli attributi.\\
\textbf{Sintassi:}
\begin{verbatim}
INSERT INTO NomeTabella [(attributi)]
VALUES (valori);
\end{verbatim}
\textcolor{verdeEsempio}{Esempi:}\\
Inserimento di una singola tupla:
\begin{verbatim}
INSERT INTO persone
VALUES ('Mario', 25, 52);
\end{verbatim}
\noindent Inserimento di più tuple:
\begin{verbatim}
INSERT INTO persone
VALUES ('Mario', 25, 52),
       ('Anna', 30, 40);
\end{verbatim}
\noindent Inserimento specificando solo alcuni attributi:
\begin{verbatim}
INSERT INTO persone (nome, reddito)
VALUES ('Lino', 55);
\end{verbatim}
\subsubsection*{2. Inserimento mediante SELECT}
Permette di inserire in una tabella le tuple ottenute come risultato di una query.\\
\textbf{Sintassi:}
\begin{verbatim}
INSERT INTO NomeTabella [(attributi)]
SELECT ...
\end{verbatim}
\textcolor{verdeEsempio}{Esempio:}
\begin{verbatim}
INSERT INTO persone (nome)
SELECT padre
FROM paternita
WHERE padre != 'Giovanni';
\end{verbatim}
\noindent Vengono inseriti nella tabella \texttt{persone} i nomi dei padri presenti nella tabella \texttt{paternita}, escludendo Giovanni.
\subsubsection*{Osservazioni su INSERT}
\begin{itemize}
    \item \textbf{L'ordine degli attributi è significativo}: ogni valore viene associato all'attributo nella posizione corrispondente.

    \item Il numero di attributi specificati deve coincidere con il numero di valori forniti.

    \item Se la lista degli attributi viene omessa, i valori devono essere forniti nell'ordine definito nel comando \texttt{CREATE TABLE}.

    \item Se vengono specificati solo alcuni attributi, quelli omessi assumono:
    \begin{itemize}
        \item il valore \texttt{DEFAULT}, se definito;
        \item il valore \texttt{NULL}, se consentito e in assenza di un valore di default.
    \end{itemize}

    \item I valori inseriti devono rispettare i vincoli di integrità della tabella.
\end{itemize}

\subsection{Eliminazione di tuple: DELETE}
Il comando \texttt{DELETE FROM} permette di eliminare le tuple di una tabella che soddisfano una determinata condizione.\\
\textbf{Sintassi:}
\begin{verbatim}
DELETE FROM NomeTabella
[WHERE condizione];
\end{verbatim}
\textcolor{verdeEsempio}{Esempi:}\\
Eliminazione delle persone con età inferiore a 35 anni:
\begin{verbatim}
DELETE FROM persone
WHERE eta < 35;
\end{verbatim}
\noindent Eliminazione delle tuple della tabella \texttt{paternita} in cui il figlio è diverso da Paolo:
\begin{verbatim}
DELETE FROM paternita
WHERE figlio != 'Paolo';
\end{verbatim}
\subsubsection*{Osservazioni su DELETE}
\begin{itemize}
    \item Vengono eliminate tutte le tuple che soddisfano la condizione specificata nella clausola \texttt{WHERE}.

    \item Se la clausola \texttt{WHERE} viene omessa, la condizione è considerata sempre vera e vengono quindi eliminate \textbf{tutte le tuple della tabella}.

    \item L'eliminazione può coinvolgere indirettamente altre tabelle in presenza di vincoli di integrità referenziale con politica \texttt{ON DELETE CASCADE}.

    \item In assenza di una politica che consenta l'eliminazione, l'operazione può essere impedita dai vincoli di integrità referenziale.
\end{itemize}
\subsection{Modifica di tuple: UPDATE}
Il comando \texttt{UPDATE} permette di modificare i valori degli attributi delle tuple di una tabella.\\
\textbf{Sintassi:}
\begin{verbatim}
UPDATE NomeTabella
SET attributo = espressione
[WHERE condizione];
\end{verbatim}
\noindent Il valore assegnato a un attributo può essere:
\begin{itemize}
    \item un valore costante;
    \item il risultato di un'espressione;
    \item il risultato di una sottoquery \texttt{SELECT};
    \item \texttt{NULL}, se consentito;
    \item \texttt{DEFAULT}, per ripristinare il valore predefinito.
\end{itemize}
È inoltre possibile modificare più attributi contemporaneamente, separando le assegnazioni con una virgola.
\subsubsection*{Esempi}
Modifica del reddito di una persona specifica:
\begin{verbatim}
UPDATE persone
SET reddito = 45
WHERE nome = 'Piero';
\end{verbatim}
Il reddito di tutte le persone chiamate Piero viene impostato a 45.
Incremento del reddito del 10\% per le persone con meno di 30 anni:
\begin{verbatim}
UPDATE persone
SET reddito = reddito * 1.1
WHERE eta < 30;
\end{verbatim}
Il nuovo reddito viene calcolato a partire dal valore precedente:
\[
\text{reddito nuovo} = \text{reddito precedente} \cdot 1.1
\]
\subsubsection*{Osservazioni su UPDATE}
\begin{itemize}
    \item La clausola \texttt{SET} specifica gli attributi da modificare e i nuovi valori da assegnare.

    \item La clausola \texttt{WHERE} individua le tuple sulle quali effettuare la modifica.

    \item Se \texttt{WHERE} viene omessa, la modifica viene applicata a \textbf{tutte le tuple della tabella}.

    \item I nuovi valori devono rispettare i vincoli di integrità definiti sulla tabella.
\end{itemize}

\section{Interrogazioni complesse}
\subsection{interrogazioni annidate}
Le \textbf{interrogazioni annidate} (o \textbf{sottoquery}) sono istruzioni \texttt{SELECT} inserite all'interno di altre query SQL, racchiuse tra parentesi.
Possono comparire in diverse parti di una query, in particolare nella clausola \texttt{WHERE}, dove permettono di:
\begin{itemize}
    \item Confrontare uno o più attributi con il risultato di una sottoquery.
    \item Verificare condizioni esistenziali, cioè la presenza di elementi che soddisfano determinate condizioni.
\end{itemize}
\subsection{Semantica delle interrogazioni annidate}
La semantica della query principale rimane invariata: per ogni tupla del prodotto cartesiano delle tabelle nella \texttt{FROM}, viene valutata la condizione nella \texttt{WHERE}.
Se la condizione contiene una sottoquery, è necessario valutarne il risultato per stabilire se la tupla soddisfa la condizione.
Concettualmente, la sottoquery viene quindi valutata per ogni tupla della query esterna, anche se il DBMS può ottimizzarne l'esecuzione.
\subsection{Operatori per le sottoquery}
Il risultato di una sottoquery può essere confrontato con uno o più attributi mediante diversi operatori.
\begin{itemize}
    \item \textbf{Operatori di confronto} (\texttt{=}, \texttt{<>}, \texttt{<}, \texttt{>}, ecc.): richiedono che la sottoquery restituisca al massimo un valore. Se non restituisce alcun valore, il confronto produce \texttt{UNKNOWN}, che nella \texttt{WHERE} non seleziona la tupla.
    \item \textbf{\texttt{ANY}}: la condizione è vera se il confronto è soddisfatto da \textbf{almeno un valore} restituito dalla sottoquery.
    \item \textbf{\texttt{ALL}}: la condizione è vera se il confronto è soddisfatto da \textbf{tutti i valori} restituiti dalla sottoquery.
    \item \textbf{\texttt{IN}}: verifica se un valore appartiene all'insieme restituito dalla sottoquery. È equivalente a \texttt{= ANY}.
    \item \textbf{\texttt{NOT IN}}: verifica se un valore non appartiene all'insieme restituito dalla sottoquery. È equivalente a \texttt{<> ALL}.
    \item \textbf{\texttt{EXISTS}}: verifica se la sottoquery restituisce almeno una tupla, indipendentemente dai valori contenuti.
\end{itemize}
\noindent
\textbf{Nota:} \texttt{ANY} restituisce \texttt{FALSE} se la sottoquery è vuota, mentre \texttt{ALL} restituisce \texttt{TRUE}. La presenza di valori \texttt{NULL} può produrre risultati \texttt{UNKNOWN} nei confronti.
\subsection{Esempi}
Si considerino le relazioni:
\begin{itemize}
    \item \texttt{persone(nome, reddito)}
    \item \texttt{paternita(padre, figlio)}
\end{itemize}
\subsubsection{1. Nome e reddito del padre di Franco}
\begin{verbatim}
SELECT nome, reddito
FROM persone
WHERE nome = (
    SELECT padre
    FROM paternita
    WHERE figlio = 'Franco'
);
\end{verbatim}
La sottoquery individua il padre di Franco, mentre la query esterna ne restituisce nome e reddito.
In questo caso si utilizza \texttt{=} perché si assume che Franco abbia un solo padre nella relazione.
\subsubsection*{2. Padri di persone con reddito superiore a 20 milioni}
\begin{verbatim}
SELECT nome, reddito
FROM persone
WHERE nome IN (
    SELECT padre
    FROM paternita, persone
    WHERE figlio = nome
      AND reddito > 20
);
\end{verbatim}
La sottoquery individua i padri delle persone con reddito superiore a 20 milioni.
La query esterna restituisce nome e reddito di tali padri.
Si utilizza \texttt{IN} perché la sottoquery può restituire più valori.
La condizione può essere scritta equivalentemente utilizzando \texttt{= ANY}:
\begin{verbatim}
WHERE nome = ANY (
    SELECT padre
    FROM paternita, persone
    WHERE figlio = nome
      AND reddito > 20
);
\end{verbatim}
\subsubsection*{3. Sottoquery annidate su più livelli}
È possibile inserire una sottoquery all'interno di un'altra sottoquery:
\begin{verbatim}
SELECT nome, reddito
FROM persone
WHERE nome IN (
    SELECT padre
    FROM paternita
    WHERE figlio IN (
        SELECT nome
        FROM persone
        WHERE reddito > 20
    )
);
\end{verbatim}
L'esecuzione logica procede dall'interno verso l'esterno:
\begin{enumerate}
    \item La query più interna individua le persone con reddito superiore a 20 milioni.
    \item La query intermedia individua i loro padri.
    \item La query esterna restituisce nome e reddito dei padri individuati.
\end{enumerate}
\subsubsection*{4. Sottoquery con operatore ALL}
Trovare i nomi delle persone che hanno un reddito maggiore di quello di tutte le persone con meno di 30 anni.
\begin{verbatim}
SELECT nome
FROM persone
WHERE reddito > ALL (
    SELECT reddito
    FROM persone
    WHERE eta < 30
);
\end{verbatim}
La sottoquery restituisce i redditi delle persone con meno di 30 anni.
La query esterna seleziona soltanto le persone il cui reddito è superiore a \textbf{tutti i redditi} restituiti dalla sottoquery.
In particolare:
\begin{itemize}
    \item La condizione è vera se il reddito è maggiore di ogni valore restituito.
    \item Se la sottoquery è vuota, la condizione con \texttt{ALL} è vera.
\end{itemize}
\subsubsection*{5. Utilizzo dell'operatore EXISTS}
L'operatore \texttt{EXISTS} verifica se il risultato di una sottoquery è \textbf{non vuoto}.
Restituisce:
\begin{itemize}
    \item \texttt{TRUE} se la sottoquery restituisce almeno una tupla.
    \item \texttt{FALSE} se la sottoquery non restituisce alcuna tupla.
\end{itemize}
\textcolor{verdeEsempio}{Esempio:} trovare tutte le persone che hanno almeno un figlio.
\begin{verbatim}
SELECT *
FROM persone p
WHERE EXISTS (
    SELECT *
    FROM paternita
    WHERE padre = p.nome
)
OR EXISTS (
    SELECT *
    FROM maternita
    WHERE madre = p.nome
);
\end{verbatim}
La query verifica due condizioni:
\begin{enumerate}
    \item La prima sottoquery controlla se la persona compare come padre nella relazione \texttt{paternita}.
    \item La seconda sottoquery controlla se la persona compare come madre nella relazione \texttt{maternita}.
\end{enumerate}
Grazie all'operatore \texttt{OR}, è sufficiente che almeno una delle due condizioni sia vera.\medskip\\
\textbf{Funzionamento logico:}
\begin{enumerate}
    \item Si considera una tupla della tabella esterna \texttt{persone}.
    \item Si eseguono logicamente le sottoquery utilizzando il valore \texttt{p.nome} della tupla corrente.
    \item Si verifica se almeno una delle sottoquery restituisce una tupla.
    \item Se la condizione è vera, la persona viene inclusa nel risultato.
\end{enumerate}

\subsection{Semantica e visibilità delle interrogazioni annidate}
\subsubsection*{Semantica}
Nelle interrogazioni annidate, una sottoquery correlata viene
\textbf{concettualmente valutata per ogni tupla della query esterna},
utilizzando i valori degli attributi della tupla corrente.
\subsubsection*{Regole di visibilità}
La \textbf{visibilità} determina quali attributi e alias possono essere
utilizzati all'interno di una sottoquery.
Le regole principali sono:
\begin{itemize}
    \item Una sottoquery può accedere agli attributi delle tabelle
    dichiarate nella propria clausola \texttt{FROM}.
    
    \item Può accedere anche agli attributi delle query esterne
    che la contengono.
    
    \item Le tabelle e gli alias definiti nelle query interne
    \textbf{non sono visibili nelle query esterne}.
    
    \item Se due livelli definiscono attributi con lo stesso nome,
    prevale quello del \textbf{livello più interno} (mascheramento).
    
    \item Se un attributo non è qualificato, SQL cerca il suo nome
    a partire dal livello corrente, procedendo verso quelli esterni.
    Se nello stesso livello il riferimento è ambiguo, viene generato
    un errore.
\end{itemize}
\subsubsection*{visibilità degli attributi esterni}
Trovare le persone che hanno almeno un figlio.
\begin{verbatim}
SELECT *
FROM persone
WHERE EXISTS (
    SELECT *
    FROM paternita
    WHERE padre = nome
)
OR EXISTS (
    SELECT *
    FROM maternita
    WHERE madre = nome
);
\end{verbatim}
L'attributo \texttt{nome} non appartiene alle tabelle
\texttt{paternita} e \texttt{maternita}, quindi viene cercato
nella query esterna, dove è presente nella tabella \texttt{persone}.
Le sottoquery sono quindi \textbf{correlate}, poiché utilizzano
un attributo della query esterna.
\subsubsection*{visibilità tra sottoquery}
Si consideri la seguente interrogazione:
\begin{verbatim}
SELECT *
FROM impiegato
WHERE dipart IN (
    SELECT nome
    FROM dipartimento D1
    WHERE nome = 'Produzione'
)
OR dipart IN (
    SELECT nome
    FROM dipartimento D2
    WHERE D2.citta = D1.citta
);
\end{verbatim}
Questa interrogazione è \textbf{scorretta}.
L'alias \texttt{D1} è definito nella prima sottoquery,
mentre viene utilizzato nella seconda.
Le due sottoquery si trovano allo stesso livello di annidamento:
\textbf{gli alias definiti in una sottoquery non sono visibili
nelle altre sottoquery dello stesso livello}.
Di conseguenza, il riferimento \texttt{D1.citta} non è valido.

\subsubsection*{Visibilità delle variabili nei blocchi interni}
Gli attributi delle tabelle definite in una sottoquery
\textbf{non possono essere utilizzati direttamente nella
clausola SELECT della query esterna}.\\
\textcolor{verdeEsempio}{Esempio:} trovare nome e reddito dei padri di persone
che guadagnano più di 20 milioni, indicando anche il reddito del figlio.
La seguente interrogazione è corretta:
\begin{verbatim}
SELECT DISTINCT p.nome, p.reddito, f.reddito
FROM persone p, paternita, persone f
WHERE p.nome = padre
  AND figlio = f.nome
  AND f.reddito > 20;
\end{verbatim}
In questo caso:
\begin{itemize}
    \item \texttt{p} rappresenta il padre.
    \item \texttt{f} rappresenta il figlio.
    \item Entrambi gli alias sono definiti nella stessa
    clausola \texttt{FROM}, quindi i rispettivi attributi
    sono visibili nella \texttt{SELECT}.
\end{itemize}
Non sarebbe invece corretto scrivere:
\begin{verbatim}
SELECT nome, reddito, f.reddito
FROM persone
WHERE nome IN (
    SELECT padre
    FROM paternita
    WHERE figlio IN (
        SELECT nome
        FROM persone f
        WHERE f.reddito > 20
    )
);
\end{verbatim}
L'errore è nel riferimento \texttt{f.reddito} della
\texttt{SELECT} esterna.
L'alias \texttt{f} è definito soltanto nella sottoquery
più interna e \textbf{non è visibile nella query esterna}.

\subsection{Interrogazioni annidate e correlate}
Una \textbf{sottoquery correlata} può utilizzare attributi o alias
definiti nella query esterna.
Questo permette di esprimere condizioni che dipendono dalla tupla
attualmente considerata nella query principale.
\subsubsection*{condizioni universali con NOT EXISTS}
Trovare i padri i cui figli guadagnano \textbf{tutti più di 20 milioni}.
\begin{verbatim}
SELECT DISTINCT z.padre
FROM paternita z
WHERE NOT EXISTS (
    SELECT *
    FROM paternita p
    JOIN persone f ON p.figlio = f.nome
    WHERE z.padre = p.padre
      AND f.reddito <= 20
);
\end{verbatim}
La query utilizza \texttt{NOT EXISTS} per verificare che
\textbf{non esista alcun figlio} con reddito minore o uguale a 20 milioni.
Il funzionamento è il seguente:
\begin{enumerate}
    \item La query esterna considera i padri presenti in
    \texttt{paternita}, identificati dall'alias \texttt{z}.

    \item La sottoquery cerca eventuali figli dello stesso padre
    con reddito minore o uguale a 20 milioni.
    
    \item La condizione \texttt{z.padre = p.padre} collega
    la sottoquery alla query esterna, rendendola \textbf{correlata}.
    
    \item \texttt{NOT EXISTS} è vero soltanto se la sottoquery
    non restituisce alcuna tupla.
    
    \item \texttt{DISTINCT} elimina eventuali duplicati,
    restituendo ciascun padre una sola volta.
\end{enumerate}
\noindent
\textbf{Concetto fondamentale:}
Una condizione universale, cioè valida per \textbf{tutti}
gli elementi, può essere espressa verificando che
\textbf{non esistano elementi che la violano}.
\subsection{Differenza mediante annidamento}
\noindent
\begin{minipage}[c]{0.38\textwidth}
\footnotesize
\begin{verbatim}
SELECT nome
FROM impiegato
EXCEPT
SELECT cognome AS nome
FROM impiegato
\end{verbatim}
\end{minipage}%
\hspace{0.3cm}%
$\Longleftrightarrow$%
\hspace{0.3cm}%
\begin{minipage}[c]{0.5\textwidth}
\footnotesize
\begin{verbatim}
SELECT nome
FROM impiegato
WHERE nome NOT IN (
    SELECT cognome
    FROM impiegato)
\end{verbatim}
\end{minipage}
\subsection{Intersezione mediante annidamento}
\begin{minipage}[c]{0.38\textwidth}
\footnotesize
\begin{verbatim}

    INTERSECTION
SELECT cognome as nome from impiegato 
\end{verbatim}
\end{minipage}
\hspace{0.3cm}

\hspace{0.3cm}

\end{verbatim}
\end{minipage}

\subsection{Condizione su più attributi con annidamento}
Le interrogazioni annidate permettono di confrontare anche
\textbf{tuple composte da più attributi}, anziché singoli valori.
Per rappresentare una tupla si utilizza una lista di attributi
separati da virgole e racchiusi tra parentesi tonde:
\[
(\texttt{attributo1}, \texttt{attributo2}, \ldots)
\]
\subsubsection*{Esempio: confronto tra coppie di attributi}
Trovare le persone che hanno una coppia
\textbf{(età, reddito) diversa da quella di tutte le altre persone}.
\begin{verbatim}
SELECT *
FROM persone p
WHERE (eta, reddito) NOT IN (
    SELECT eta, reddito
    FROM persone
    WHERE nome <> p.nome
);
\end{verbatim}
Il funzionamento è il seguente:
\begin{enumerate}
    \item La query esterna considera una persona \texttt{p}.
    \item La sottoquery restituisce le coppie
    \texttt{(eta, reddito)} di tutte le altre persone.
    \item \texttt{NOT IN} verifica che la coppia della persona
    corrente non sia presente tra quelle restituite.
    \item Se la condizione è vera, la persona viene selezionata.
\end{enumerate}
La sottoquery è \textbf{correlata}, poiché utilizza
\texttt{p.nome}, definito nella query esterna.

\section{Interrogazioni annidate nella clausola FROM}
Le sottoquery possono comparire anche nella clausola \texttt{FROM},
oltre che nella \texttt{WHERE}.
In questo caso prendono il nome di \textbf{query derivate},
\textbf{viste inline} o \textbf{table expression}.
Una vista inline è una \textbf{tabella temporanea calcolata}
attraverso una query \texttt{SELECT}, il cui risultato viene
utilizzato come tabella nella query esterna.
\textbf{Caratteristiche principali:}
\begin{itemize}
    \item La sottoquery deve essere racchiusa tra parentesi tonde.
    \item Deve avere un \textbf{alias}, utilizzato per riferirsi
    alla tabella derivata.
    \item Può essere utilizzata come una normale tabella
    nelle operazioni di \texttt{JOIN}.
    \item Può contenere aggregazioni, \texttt{GROUP BY}
    e altre operazioni SQL.
\end{itemize}
\subsubsection*{Esempio: vista inline nella FROM}
Trovare i padri delle persone con più di 30 anni.
\begin{verbatim}
SELECT p.padre
FROM paternita p,
     (SELECT nome
      FROM persone
      WHERE eta > 30) f
WHERE f.nome = p.figlio;
\end{verbatim}
La sottoquery genera una tabella temporanea \texttt{f}
contenente i nomi delle persone con più di 30 anni.
La query esterna confronta tali nomi con l'attributo
\texttt{figlio} della relazione \texttt{paternita},
restituendo i rispettivi padri.
\subsection{Utilizzo con JOIN esplicito}
La stessa interrogazione può essere scritta utilizzando
un \texttt{JOIN} esplicito:
\begin{verbatim}
SELECT p.padre
FROM paternita p
JOIN (
    SELECT nome
    FROM persone
    WHERE eta > 30
) f ON f.nome = p.figlio;
\end{verbatim}
Le due interrogazioni sono \textbf{equivalenti}:
la differenza riguarda soltanto la sintassi utilizzata
per effettuare il collegamento tra le tabelle.
\subsection{Viste inline e aggregazioni}
Le viste inline sono particolarmente utili quando
si vuole effettuare un \texttt{JOIN} con il risultato
di una \textbf{query aggregata}.\\
\textcolor{verdeEsempio}{Esempio:} per ogni persona, trovare il nome,
l'età e il numero di persone che hanno la stessa età.
\begin{verbatim}
SELECT p.nome, p.eta, v.conta
FROM persona p
JOIN (
    SELECT eta, COUNT(*) AS conta
    FROM persona
    GROUP BY eta
) v ON p.eta = v.eta;
\end{verbatim}
Il funzionamento è il seguente:
\begin{enumerate}
    \item La sottoquery raggruppa le persone per età
    mediante \texttt{GROUP BY}.
    
    \item Per ogni età calcola il numero di persone
    attraverso \texttt{COUNT(*)}.
    
    \item Il risultato viene trattato come una tabella
    temporanea identificata dall'alias \texttt{v}.
    
    \item La query esterna effettua un \texttt{JOIN}
    tra ogni persona e il gruppo corrispondente
    alla sua età.
\end{enumerate}
In questo modo, a ogni persona viene associato
il numero totale di persone della sua stessa età.
\subsection{Aggregazioni su query aggregate}
Le viste inline permettono anche di eseguire
\textbf{aggregazioni sul risultato di altre aggregazioni}.\\
\textcolor{verdeEsempio}{Esempio:} determinare, per ogni possibile numero
di figli, quante madri hanno esattamente quel numero di figli.
\begin{verbatim}
SELECT t.conta AS numfigli, COUNT(*) AS numgenitori
FROM (
    SELECT genitore, COUNT(*) AS conta
    FROM genia
    GROUP BY genitore
) t
GROUP BY t.conta;
\end{verbatim}
La query contiene \textbf{due livelli di aggregazione}:
\begin{enumerate}
    \item \textbf{Aggregazione interna:}
    \begin{itemize}
        \item Raggruppa le tuple per \texttt{genitore}.
        \item Conta il numero di figli di ciascun genitore.
        \item Produce una tabella con gli attributi
        \texttt{genitore} e \texttt{conta}.
    \end{itemize}
    \item \textbf{Aggregazione esterna:}
    \begin{itemize}
        \item Raggruppa i genitori in base al numero
        di figli (\texttt{t.conta}).
        \item Conta quanti genitori hanno lo stesso
        numero di figli.
    \end{itemize}
\end{enumerate}

\subsection{Importanza delle viste inline e clausola WITH}
Le \textbf{viste inline} permettono di utilizzare il risultato
di una sottoquery come tabella temporanea nella clausola \texttt{FROM}.
Sono particolarmente utili per combinare risultati di più query
e applicare successivamente operazioni di aggregazione.
\subsubsection*{Esempio: media dei voti di tutti gli esami}
Si considerino le relazioni:
\begin{itemize}
    \item \texttt{EsamiTriennale(matricola, corso, voto)}
    \item \texttt{EsamiMagistrale(matricola, corso, voto)}
\end{itemize}
Si vuole calcolare la \textbf{media dei voti di tutti gli esami}
(triennale e magistrale) per ciascuno studente.
\begin{verbatim}
SELECT v.matricola, AVG(v.voto)
FROM (
    SELECT matricola, corso, voto
    FROM EsamiTriennale
    UNION
    SELECT matricola, corso, voto
    FROM EsamiMagistrale
) v
GROUP BY v.matricola;
\end{verbatim}
Il funzionamento è il seguente:
\begin{enumerate}
    \item La sottoquery combina gli esami della triennale
    e della magistrale mediante \texttt{UNION}.
    
    \item Il risultato viene trattato come una tabella
    temporanea identificata dall'alias \texttt{v}.
    
    \item La query esterna raggruppa gli esami per
    \texttt{matricola}.
    
    \item \texttt{AVG(v.voto)} calcola la media dei voti
    di ciascuno studente.
\end{enumerate}
\subsubsection{La clausola WITH}
La clausola \texttt{WITH} permette di definire una o più
\textbf{tabelle temporanee nominate}, dette anche
\textbf{CTE} (\textit{Common Table Expressions}).
Queste tabelle possono essere utilizzate nella query
principale come normali relazioni.
La clausola \texttt{WITH} rappresenta quindi un'alternativa
alle viste inline, rendendo le interrogazioni più leggibili
e modulari.
\subsubsection*{Esempio: media dei voti con WITH}
La query precedente può essere riscritta come:
\begin{verbatim}
WITH miavista(mat, cor, vot) AS (
    SELECT matricola, corso, voto
    FROM EsamiTriennale
    UNION
    SELECT matricola, corso, voto
    FROM EsamiMagistrale
)
SELECT miavista.mat, AVG(miavista.vot)
FROM miavista
GROUP BY miavista.mat;
\end{verbatim}
In questo caso:
\begin{itemize}
    \item \texttt{WITH} definisce una tabella temporanea
    chiamata \texttt{miavista}.
    
    \item \texttt{(mat, cor, vot)} specifica i nomi
    degli attributi della tabella temporanea.
    
    \item La query principale utilizza \texttt{miavista}
    nella clausola \texttt{FROM} come una normale tabella.
\end{itemize}

\subsubsection*{Definizione di più viste con WITH}
È possibile definire \textbf{più tabelle temporanee}
all'interno della stessa clausola \texttt{WITH}.
La sintassi generale è:
\begin{verbatim}
WITH V1 AS (
    SELECT ...
),
V2 AS (
    SELECT ...
),
...
Vn AS (
    SELECT ...
)
SELECT ...
FROM ...
WHERE ...;
\end{verbatim}
Le viste \texttt{V1}, \texttt{V2}, \ldots, \texttt{Vn}
possono essere utilizzate nella query principale
come normali tabelle.
Inoltre, una CTE può fare riferimento alle CTE
definite precedentemente nella stessa clausola
\texttt{WITH}.
\medskip
\noindent
\textbf{Differenza tra viste inline e WITH:}
\begin{itemize}
    \item \textbf{Vista inline}: la sottoquery è definita
    direttamente nella clausola \texttt{FROM}.
    
    \item \textbf{WITH}: la sottoquery viene definita
    prima della query principale e associata a un nome.
    
    \item Entrambe permettono di utilizzare risultati
    intermedi come tabelle, ma \texttt{WITH} facilita
    la lettura e il riutilizzo delle sottoquery.
\end{itemize}
\section{Interrogazioni annidate nella target list}
Finora abbiamo visto interrogazioni annidate nelle clausole
\texttt{WHERE} e \texttt{FROM}. Tuttavia, è possibile
inserire sottoquery anche nella \textbf{target list},
ovvero nella clausola \texttt{SELECT}.
In questo caso, la sottoquery deve restituire
\textbf{un solo valore} per ogni tupla della query esterna.\\
\textcolor{verdeEsempio}{Esempio: }
Vogliamo ottenere il nome di ogni persona con reddito
maggiore di 10 e, accanto al nome, il numero di persone
che hanno la sua stessa età.
\begin{verbatim}
SELECT p.nome,
       (SELECT COUNT(*)
        FROM persone
        WHERE eta = p.eta)
FROM persone p
WHERE p.reddito > 10;
\end{verbatim}
La sottoquery nella clausola \texttt{SELECT} è
\textbf{correlata}, poiché utilizza l'attributo
\texttt{p.eta}, che appartiene alla query esterna.\\
\textbf{Semantica:}
\begin{itemize}
    \item La query esterna seleziona le persone
    con reddito maggiore di 10.
    \item Per ogni persona selezionata viene
    eseguita logicamente la sottoquery.
    \item La sottoquery conta quante persone
    hanno la stessa età della persona corrente.
    \item Il risultato viene riportato accanto
    al nome della persona.
\end{itemize}
Quindi, per ogni tupla della query esterna,
la target list viene calcolata valutando
anche la sottoquery presente al suo interno.
\section{Interrogazioni annidate nella clausola HAVING}
Le sottoquery possono comparire anche nella
clausola \texttt{HAVING}, utilizzata per
\textbf{filtrare i gruppi} prodotti da
\texttt{GROUP BY}.\\
\textcolor{verdeEsempio}{Esempio: }\\
Vogliamo conoscere le età delle persone
per le quali la somma dei redditi delle persone
con quella età è \textbf{massima}.
Assumiamo che non siano presenti valori
\texttt{NULL} nell'attributo \texttt{reddito}.
\begin{verbatim}
SELECT eta
FROM persone
GROUP BY eta
HAVING SUM(reddito) >= ALL (
    SELECT SUM(reddito)
    FROM persone
    GROUP BY eta
);
\end{verbatim}
\textbf{Funzionamento:}
\begin{enumerate}
    \item La query esterna raggruppa le persone
    in base all'età mediante \texttt{GROUP BY eta}.

    \item Per ogni gruppo viene calcolata
    la somma dei redditi con \texttt{SUM(reddito)}.

    \item La sottoquery calcola tutte le somme
    dei redditi, una per ciascuna età.

    \item La condizione
    \texttt{>= ALL} verifica che la somma
    del gruppo corrente sia maggiore o uguale
    a tutte le somme restituite dalla sottoquery.
\end{enumerate}
Vengono quindi selezionate soltanto le età
che corrispondono alla \textbf{somma massima
dei redditi}.
Se più età hanno la stessa somma massima,
vengono restituite tutte.
\medskip\\
\noindent
\textbf{Osservazione:}
l'operatore \texttt{ALL} permette di confrontare
un valore con tutti quelli restituiti
da una sottoquery.
\section{Ulteriori aspetti di SQL}
\subsection{Case}
Nella \textbf{target list} può essere utile produrre un valore
che dipende da una serie di condizioni.
A questo scopo SQL mette a disposizione la clausola
\texttt{CASE}, che permette di costruire espressioni condizionali.
\subsubsection*{Sintassi}
\begin{verbatim}
CASE
    WHEN <condizione> THEN <espressione>
    ...
    WHEN <condizione> THEN <espressione>
    ELSE <espressione>
END
\end{verbatim}
La clausola \texttt{ELSE} è facoltativa.\\
\textbf{Semantica:}\\
Le condizioni vengono valutate nell'ordine in cui compaiono.
Il valore restituito è:
\begin{itemize}
    \item L'espressione associata alla
    \textbf{prima condizione vera}.

    \item L'espressione specificata dopo
    \texttt{ELSE}, se nessuna condizione è vera.

    \item \texttt{NULL}, se nessuna condizione
    è vera e la clausola \texttt{ELSE} è assente.
\end{itemize}

\noindent \textcolor{verdeEsempio}{Esempio: }\\
Consideriamo la relazione:
\[
\text{Persona(nome, eta, reddito)}
\]
Vogliamo selezionare le persone con età maggiore di 10,
aggiungendo un attributo \texttt{fasciaeta} che assume
i seguenti valori:
\begin{itemize}
    \item \texttt{ragazzo}: età minore o uguale a 20.
    \item \texttt{adulto}: età maggiore di 20 e
    minore o uguale a 50.
    \item \texttt{anziano}: età maggiore di 50.
\end{itemize}
\begin{verbatim}
SELECT nome,
       CASE
           WHEN eta <= 20 THEN 'ragazzo'
           WHEN eta > 20 AND eta <= 50
                THEN 'adulto'
           ELSE 'anziano'
       END AS fasciaeta,
       reddito
FROM Persona
WHERE eta > 10;
\end{verbatim}
La clausola \texttt{CASE} viene valutata per ogni
tupla selezionata dalla query.
L'espressione \texttt{END AS fasciaeta} assegna
il nome \texttt{fasciaeta} alla nuova colonna.

\subsection{CHECK}
La clausola \texttt{CHECK} permette di specificare
\textbf{vincoli di integrità} che devono essere
rispettati dai dati di una tabella.
La sintassi generale è:
\begin{verbatim}
CHECK (<condizione>)
\end{verbatim}
Il vincolo può essere definito su un singolo attributo
oppure sull'intera tabella.\\
\textcolor{verdeEsempio}{Esempio}
\begin{verbatim}
CREATE TABLE impiegato
(
    matricola CHARACTER(6),
    cognome CHARACTER(20),
    nome CHARACTER(20),
    sesso CHARACTER  NOT NULL CHECK (sesso IN ('M', 'F')),
    stipendio INTEGER,
    superiore CHARACTER(6)
);
\end{verbatim}
\textbf{Primo vincolo:}
\begin{verbatim}
CHECK (sesso IN ('M', 'F'))
\end{verbatim}
L'attributo \texttt{sesso} può assumere
soltanto i valori \texttt{'M'} e \texttt{'F'}.
Inoltre, grazie a \texttt{NOT NULL},
non può assumere il valore nullo.\\
\noindent
\textbf{Nota:} un vincolo \texttt{CHECK} è soddisfatto
quando la condizione risulta vera oppure sconosciuta
(\texttt{UNKNOWN}).
\subsection{Viste}
Una \textbf{vista} è una tabella la cui istanza
è derivata da altre tabelle mediante
un'interrogazione SQL.
Per definire una vista si utilizza:
\begin{verbatim}
CREATE VIEW NomeVista [(ListaAttributi)]
AS
SELECT ...
\end{verbatim}
Le viste sono generalmente considerate
\textbf{tabelle virtuali}.
La loro definizione viene memorizzata nella base
di dati, mentre il risultato dell'interrogazione
viene normalmente calcolato quando la vista
viene utilizzata.\\
\textcolor{verdeEsempio}{Esempio}\\
Vogliamo creare una vista contenente gli impiegati
del dipartimento Amministrazione con stipendio
maggiore di 10.
\begin{verbatim}
CREATE VIEW ImpAmmin(Mat, Nome, Cognome, Stip)
AS
SELECT Matricola, Nome, Cognome, Stipendio
FROM Impiegato
WHERE Dipart = 'Amministrazione'
  AND Stipendio > 10;
\end{verbatim}
La vista \texttt{ImpAmmin} contiene quattro attributi:
\begin{itemize}
    \item \texttt{Mat}
    \item \texttt{Nome}
    \item \texttt{Cognome}
    \item \texttt{Stip}
\end{itemize}
Questi attributi corrispondono alle colonne
restituite dalla query associata alla vista.
Una volta definita, la vista può essere
interrogata come una normale tabella.
Ad esempio:
\begin{verbatim}
SELECT *
FROM ImpAmmin;
\end{verbatim}
\subsection{Utilizzo delle viste nelle interrogazioni}
Consideriamo nuovamente il problema:
\begin{quote}
Voglio sapere l'età delle persone cui corrisponde il massimo reddito
\end{quote}
Abbiamo già visto una soluzione che utilizza
una sottoquery nella clausola \texttt{HAVING}.
\begin{verbatim}
SELECT eta
FROM persone
GROUP BY eta
HAVING SUM(reddito) >= ALL (
    SELECT SUM(reddito)
    FROM persone
    GROUP BY eta
);
\end{verbatim}
Un'alternativa consiste nel definire una vista.
\subsubsection*{Soluzione mediante una vista}
Per prima cosa creiamo una vista che associa
a ogni età la somma dei redditi delle persone
con quella età.
\begin{verbatim}
CREATE VIEW etaReddito(eta, totaleReddito)
AS
SELECT eta, SUM(reddito)
FROM persone
GROUP BY eta;
\end{verbatim}
La vista contiene due attributi:
\begin{itemize}
    \item \texttt{eta}: età delle persone.
    \item \texttt{totaleReddito}: somma dei redditi
    delle persone con quella età.
\end{itemize}
Successivamente possiamo individuare le età
con reddito complessivo massimo:
\begin{verbatim}
SELECT eta
FROM etaReddito
WHERE totaleReddito = (
    SELECT MAX(totaleReddito)
    FROM etaReddito
);
\end{verbatim}
\noindent Se più età hanno lo stesso reddito complessivo
massimo, vengono restituite tutte.
\medskip\\
\noindent
\textbf{Vantaggio:}
L'utilizzo di una vista permette di separare
il calcolo delle somme dalla ricerca del massimo,
rendendo l'interrogazione più leggibile
e consentendo di riutilizzare il risultato logico
del raggruppamento in altre query.
\subsection{Tabelle e viste temporanee}
In molti DBMS è possibile creare
\textbf{tabelle temporanee}, cioè tabelle
che esistono soltanto per un periodo limitato.
Generalmente, una tabella temporanea viene
eliminata automaticamente al termine della
sessione di connessione al database.
\subsubsection*{Creazione di una tabella temporanea}
\begin{verbatim}
CREATE TEMPORARY TABLE MiaTabella (
    id INTEGER,
    nome VARCHAR(50)
);
\end{verbatim}
La tabella \texttt{MiaTabella} può essere
utilizzata durante la sessione corrente.
Al termine della sessione viene eliminata
automaticamente.
\subsubsection*{Eliminazione esplicita}
È possibile eliminare una tabella prima
della fine della sessione:
\begin{verbatim}
DROP TABLE MiaTabella;
\end{verbatim}
Analogamente, una vista può essere eliminata
mediante:
\begin{verbatim}
DROP VIEW NomeVista;
\end{verbatim}
\subsubsection*{Viste temporanee}
Alcuni DBMS permettono anche di definire
viste temporanee.
Ad esempio, PostgreSQL supporta:
\begin{verbatim}
CREATE TEMPORARY VIEW MiaVista AS
SELECT *
FROM Impiegato
WHERE Stipendio > 10;
\end{verbatim}
La disponibilità e il comportamento delle
viste temporanee dipendono dal DBMS utilizzato.

\section{Transazioni}
\subsection{Definizione}
Una \textbf{transazione} è un insieme di operazioni su una
base di dati che devono essere eseguite come un'unica
unità logica di lavoro.\\
Una transazione deve garantire che:
\begin{itemize}
    \item le operazioni siano eseguite interamente oppure
    non abbiano alcun effetto;
    \item i vincoli di integrità della base di dati siano
    rispettati;
    \item l'esecuzione contemporanea di più transazioni
    non produca risultati scorretti;
    \item i risultati delle transazioni completate
    rimangano memorizzati anche in presenza di guasti.
\end{itemize}
\noindent Queste caratteristiche sono riassunte dalle
\textbf{proprietà ACID}:
\begin{itemize}
    \item \textbf{A}tomicità;
    \item \textbf{C}onsistenza;
    \item \textbf{I}solamento;
    \item \textbf{D}urabilità (o persistenza).
\end{itemize}

\subsection{Proprietà ACID}

\subsubsection{Atomicità (Atomicity)}

Una transazione è \textbf{atomica} se tutte le operazioni
che la compongono vengono eseguite completamente oppure
nessuna di esse produce effetti permanenti.\\
\textcolor{verdeEsempio}{Esempio:}\\
Supponiamo di voler trasferire 100 euro dal conto A
al conto B.\\
Le operazioni necessarie sono:
\begin{enumerate}
    \item Sottrarre 100 euro dal conto A.
    \item Aggiungere 100 euro al conto B.
\end{enumerate}
\noindent Se si verifica un errore dopo il prelievo dal conto A,
ma prima del versamento sul conto B, il sistema deve
annullare anche il prelievo.
Quindi:
\[
\text{Transazione} =
\begin{cases}
\text{entrambe le operazioni}, & \text{se tutto va bene}\\
\text{nessuna operazione}, & \text{in caso di errore}
\end{cases}
\]
L'annullamento delle modifiche prende il nome di
\textbf{rollback}.
\subsubsection{Consistenza (Consistency)}
Una transazione è \textbf{consistente} se porta la base
di dati da uno stato valido a un altro stato valido,
rispettando tutti i vincoli di integrità.
Durante l'esecuzione possono essere temporaneamente
violati alcuni vincoli, purché quelli che devono essere
verificati alla fine della transazione risultino
soddisfatti prima del commit.
In particolare, alcuni vincoli possono essere
\textbf{differibili (deferrable)}, cioè controllati
alla conclusione della transazione.
In SQL, nei DBMS che lo supportano, è possibile
posticiparne il controllo mediante:
\begin{verbatim}
SET CONSTRAINTS ALL DEFERRED;
\end{verbatim}
\textbf{Attenzione:} questa istruzione riguarda
soltanto i vincoli dichiarati differibili.
Se al momento del commit un vincolo di integrità
risulta ancora violato, la transazione non può
essere confermata e deve essere annullata.\\
\textcolor{verdeEsempio}{Esempio:}\\
Supponiamo che il saldo di un conto non possa essere
negativo.
Una transazione che porta il saldo da 100 euro
a -50 euro viola il vincolo:
\[
Saldo \geq 0
\]
Se tale violazione permane al momento della verifica
del vincolo, la transazione viene rifiutata.
\subsubsection{Isolamento (Isolation)}
Una transazione è \textbf{isolata} se la sua esecuzione
concorrente con altre transazioni non produce
interferenze scorrette.
In particolare, il DBMS deve controllare
l'interazione tra transazioni che accedono
contemporaneamente agli stessi dati.
Un'esecuzione è \textbf{serializzabile} quando il risultato
dell'esecuzione concorrente è equivalente a quello
di una qualche esecuzione seriale.\\
\textcolor{verdeEsempio}{Esempio:}\\
Supponiamo che il saldo iniziale di un conto sia:
\[
Saldo = 1000
\]
Due transazioni concorrenti devono sottrarre
rispettivamente 100 e 200 euro.
Il risultato corretto è:
\[
Saldo_{\text{finale}} = 1000 - 100 - 200 = 700
\]
Senza un adeguato isolamento, entrambe le transazioni
potrebbero leggere il saldo iniziale di 1000 euro
e sovrascrivere reciprocamente i risultati.
Si potrebbe quindi ottenere erroneamente:
\[
Saldo_{\text{finale}} = 900
\]
oppure:
\[
Saldo_{\text{finale}} = 800
\]
Questo problema prende il nome di
\textbf{lost update} (aggiornamento perso).
L'isolamento serve a prevenire queste anomalie.
\subsubsection{Durabilità (Durability)}
Una transazione è \textbf{durevole} se, una volta
confermata, le modifiche apportate alla base di dati
rimangono permanenti.
La conferma di una transazione avviene mediante
l'operazione:
\begin{verbatim}
COMMIT;
\end{verbatim}
Dopo il commit, il DBMS garantisce la persistenza
delle modifiche anche in presenza di guasti
del sistema, secondo le garanzie di durabilità
offerte dal sistema stesso.\\
\textcolor{verdeEsempio}{Esempio:}\\
Se trasferiamo 100 euro dal conto A al conto B
e la transazione termina con successo, un successivo
riavvio del database non deve annullare il trasferimento.
\subsection{Gestione delle transazioni in SQL}
SQL mette a disposizione alcune istruzioni fondamentali
per gestire le transazioni.
\subsubsection{BEGIN}
L'istruzione:
\begin{verbatim}
BEGIN TRANSACTION;
\end{verbatim}
indica l'inizio di una transazione esplicita.
Le operazioni successive appartengono alla stessa
transazione fino alla sua conclusione.
\subsubsection{COMMIT}
L'istruzione:
\begin{verbatim}
COMMIT;
\end{verbatim}
conferma la transazione e rende definitive
le modifiche effettuate.
\subsubsection{ROLLBACK}
L'istruzione:
\begin{verbatim}
ROLLBACK;
\end{verbatim}
annulla le modifiche effettuate dalla transazione
corrente, riportando i dati allo stato precedente
alla transazione.
\paragraph{Schema generale}
\begin{verbatim}
BEGIN TRANSACTION;
-- Operazione 1
-- Operazione 2
-- ...
-- Operazione N
COMMIT;
\end{verbatim}
Se si verifica un errore che richiede
l'annullamento della transazione, si utilizza:
\begin{verbatim}
ROLLBACK;
\end{verbatim}
\subsubsection{Esempio: trasferimento di denaro}
Consideriamo una tabella:
\begin{verbatim}
ContoCorrente(
    NumeroConto,
    Saldo
)
\end{verbatim}
Vogliamo trasferire 100 euro dal conto 12345
al conto 55555.
\subsubsection{Esecuzione senza transazione esplicita}
Supponiamo di eseguire separatamente:
\begin{verbatim}
UPDATE ContoCorrente
SET Saldo = Saldo - 100
WHERE NumeroConto = 12345;
\end{verbatim}
\begin{verbatim}
UPDATE ContoCorrente
SET Saldo = Saldo + 100
WHERE NumeroConto = 55555;
\end{verbatim}
Se le istruzioni vengono confermate separatamente,
possono verificarsi problemi.
Ad esempio, se il sistema si blocca dopo
la prima operazione, ma prima della seconda:
\begin{itemize}
    \item il conto 12345 perde 100 euro;
    \item il conto 55555 non riceve nulla.
\end{itemize}
Il trasferimento risulta quindi incompleto.
\subsubsection{Esecuzione con transazione}
Per evitare questo problema, raggruppiamo
le due operazioni in una transazione:
\begin{verbatim}
BEGIN TRANSACTION;

UPDATE ContoCorrente
SET Saldo = Saldo - 100
WHERE NumeroConto = 12345;

UPDATE ContoCorrente
SET Saldo = Saldo + 100
WHERE NumeroConto = 55555;

COMMIT;
\end{verbatim}
In questo modo, le modifiche vengono
confermate come un'unica unità logica.
Se la transazione viene annullata prima del commit,
nessuna delle due modifiche rimane permanente.
\subsubsection{Esempio: problemi di concorrenza}
Nelle slide viene considerato un trasferimento
in cui l'importo da trasferire non è costante,
ma viene letto da un'altra tabella.
Supponiamo di avere la relazione:
\[
R(A,B)
\]
e di voler trasferire l'importo:
\[
\texttt{select A from R where B=1}
\]
Assumiamo che la selezione restituisca
un unico valore numerico.
Il trasferimento prevede:
\begin{enumerate}
    \item Leggere il valore A dalla tabella R
    nella tupla con B = 1.
    \item Sottrarre tale valore dal conto 12345.
    \item Aggiungere lo stesso valore al conto 55555.
\end{enumerate}
\subsubsection{Problema senza isolamento}
Supponiamo che inizialmente:
\[
A = 100
\]
La prima operazione sottrae 100 euro
dal conto 12345.
Prima della seconda operazione, un'altra
transazione modifica il valore di A:
\[
A = 50
\]
La seconda operazione legge quindi il nuovo valore
e aggiunge soltanto 50 euro al conto 55555.
Il risultato è:
\[
\begin{aligned}
\Delta Saldo_{12345} &= -100\\
\Delta Saldo_{55555} &= +50
\end{aligned}
\]
Di conseguenza:
\[
\Delta Saldo_{\text{totale}} = -50
\]
Sono stati persi 50 euro.
Il problema nasce dal fatto che le due operazioni
hanno letto valori diversi di A.
\subsubsection{Soluzione mediante transazione serializzabile}
Per evitare questa anomalia, possiamo utilizzare
una transazione con isolamento serializzabile:
\begin{verbatim}
BEGIN TRANSACTION;

SET TRANSACTION ISOLATION LEVEL
SERIALIZABLE;

UPDATE ContoCorrente
SET Saldo = Saldo - (SELECT A FROM R WHERE B = 1)
WHERE NumeroConto = 12345;

UPDATE ContoCorrente
SET Saldo = Saldo + (SELECT A FROM R WHERE B = 1)
WHERE NumeroConto = 55555;

COMMIT;
\end{verbatim}
Il livello di isolamento \texttt{SERIALIZABLE}
garantisce che l'esecuzione concorrente sia
equivalente a una qualche esecuzione seriale.
In particolare, non deve essere possibile
confermare un risultato in cui il trasferimento
utilizzi due importi differenti a causa
di un'interferenza concorrente.
Il DBMS può ottenere questa garanzia mediante
meccanismi di controllo della concorrenza,
eventualmente bloccando o annullando
una delle transazioni coinvolte.\\
\textbf{Nota:} in caso di annullamento dovuto
a un conflitto di serializzazione, l'applicazione
può dover ripetere la transazione.

\section{Vincoli di Foreign Key e reazioni agli aggiornamenti}
\subsection{Integrità referenziale}
Un vincolo di \textbf{foreign key} (chiave esterna)
garantisce l'integrità referenziale tra due tabelle.
In particolare, una foreign key impone che ogni
valore non nullo della chiave esterna presente
in una tabella corrisponda a un valore della
chiave referenziata nell'altra tabella.
Consideriamo due tabelle:
\begin{itemize}
    \item \textbf{Tabella figlia}: contiene la foreign key.
    \item \textbf{Tabella padre}: contiene la chiave
    referenziata dalla foreign key.
\end{itemize}
La relazione tra le due tabelle è quindi:
\[
\boxed{
\text{Tabella figlia}
\xrightarrow{\text{Foreign Key}}
\text{Tabella padre}
}
\]
\textcolor{verdeEsempio}{Esempio}\\
Consideriamo le seguenti tabelle:
\begin{verbatim}
CREATE TABLE persona (
    cf VARCHAR(100) PRIMARY KEY,
    eta INTEGER
);

CREATE TABLE citta (
    nome VARCHAR(30) PRIMARY KEY,
    sindaco VARCHAR(100)
        CONSTRAINT vincolo1
        REFERENCES persona(cf)
);
\end{verbatim}
In questo caso:
\begin{itemize}
    \item \texttt{persona} è la tabella padre;
    \item \texttt{citta} è la tabella figlia;
    \item \texttt{citta.sindaco} è la foreign key;
    \item \texttt{persona.cf} è la chiave referenziata.
\end{itemize}
\noindent Supponiamo di avere:
\[
\text{persona} =
\{(2000,42)\}
\]

\[
\text{citta} =
\{(\text{Savona},2000)\}
\]
La tupla:
\[
(2000,42)
\]
è detta \textbf{tupla padre}, mentre:
\[
(\text{Savona},2000)
\]
è detta \textbf{tupla figlia}.
\subsection{Politiche di reazione ai vincoli di Foreign Key}
Quando si modifica o si elimina una tupla
della tabella padre, si potrebbe violare
un vincolo di integrità referenziale.\\
\textcolor{verdeEsempio}{Esempio} se eliminiamo dalla tabella
\texttt{persona} una persona che compare
come sindaco nella tabella \texttt{citta},
quest'ultima potrebbe contenere un riferimento
a una persona non più esistente.\\
SQL permette di specificare delle
\textbf{politiche di reazione}, cioè azioni
da eseguire quando una modifica rischia
di violare un vincolo di foreign key.
La sintassi generale è:
\begin{verbatim}
FOREIGN KEY (attributi)
REFERENCES tabella(attributi)

ON DELETE azione
ON UPDATE azione
\end{verbatim}
Dove:
\begin{itemize}
    \item \texttt{ON DELETE}: specifica cosa accade
    quando viene eliminata una tupla padre.

    \item \texttt{ON UPDATE}: specifica cosa accade
    quando viene modificata la chiave
    referenziata di una tupla padre.
\end{itemize}
\noindent Le possibili azioni sono:
\begin{itemize}
    \item \texttt{NO ACTION}
    \item \texttt{RESTRICT}
    \item \texttt{CASCADE}
    \item \texttt{SET NULL}
    \item \texttt{SET DEFAULT}
\end{itemize}
\subsubsection{NO ACTION}
La politica \texttt{NO ACTION} impedisce
che una modifica della tabella padre lasci
violato un vincolo di integrità referenziale
al momento della sua verifica.
Se si tenta di eliminare o modificare
una tupla padre ancora referenziata
da una tupla figlia, viene generato un errore
se il vincolo risulta violato al momento
del controllo.\\
\textbf{Importante:} il controllo può essere
posticipato alla fine della transazione
se il vincolo è definito come
\texttt{DEFERRABLE} ed è impostato
in modalità \texttt{DEFERRED}.\\
\textcolor{verdeEsempio}{Esempio:}\\
Supponiamo che la città di Savona
abbia come sindaco la persona con
codice fiscale \texttt{2000}.
Se eseguiamo:
\begin{verbatim}
DELETE FROM persona
WHERE cf = '2000';
\end{verbatim}
otteniamo un errore se la persona
è ancora referenziata dalla tabella
\texttt{citta} al momento della verifica.\\
\textbf{Nota:} \texttt{NO ACTION} è la
politica predefinita quando non viene
specificata un'azione.
\subsubsection{RESTRICT}
La politica \texttt{RESTRICT} impedisce
immediatamente la cancellazione o
l'aggiornamento di una tupla padre
se questa è ancora referenziata
da una tupla figlia.
La differenza principale rispetto
a \texttt{NO ACTION} riguarda
il momento del controllo.
\begin{itemize}
    \item \textbf{NO ACTION}: il controllo
    può essere differito.

    \item \textbf{RESTRICT}: il controllo
    non può essere differito.
\end{itemize}
\noindent Quindi, anche se il vincolo è differibile,
\texttt{RESTRICT} non permette di
rimandare il controllo dell'azione
referenziale alla fine della transazione.
\subsubsection{CASCADE}
La politica \texttt{CASCADE} propaga
automaticamente le modifiche effettuate
sulla tabella padre alle tuple figlie.
Il comportamento dipendedall'operazione.\medskip\\
\texttt{ON DELETE CASCADE}\\\
Quando viene eliminata una tupla padre,
vengono eliminate automaticamente anche
le tuple figlie che la referenziano.
\begin{verbatim}
FOREIGN KEY (sindaco)
REFERENCES persona(cf)
ON DELETE CASCADE
\end{verbatim}
Se eliminiamo una persona, vengono
eliminate anche le città che la
referenziano attraverso l'attributo
\texttt{sindaco}.\medskip\\
\texttt{ON UPDATE CASCADE}\\
Quando viene modificato il valore
della chiave referenziata nella
tabella padre, vengono aggiornati
automaticamente i corrispondenti
valori delle foreign key nelle
tuple figlie.
\begin{verbatim}
FOREIGN KEY (sindaco)
REFERENCES persona(cf)
ON UPDATE CASCADE
\end{verbatim}
Ad esempio, se il codice fiscale
referenziato cambia da \texttt{2000}
a \texttt{3000}, anche il valore
\texttt{sindaco} nelle città
corrispondenti viene aggiornato.
\subsubsection{SET NULL}
La politica \texttt{SET NULL}
sostituisce con \texttt{NULL}
il valore della foreign key nelle
tuple figlie coinvolte.
\begin{verbatim}
FOREIGN KEY (sindaco)
REFERENCES persona(cf)
ON DELETE SET NULL
\end{verbatim}
Se viene eliminata una persona
che è sindaco di una città,
la città rimane nella tabella,
ma il suo attributo
\texttt{sindaco} diventa \texttt{NULL}.\\
\textbf{Attenzione:} questa politica
richiede che gli attributi coinvolti
possano assumere il valore \texttt{NULL}.
Se la foreign key è dichiarata
\texttt{NOT NULL}, l'operazione
non può completarsi con successo.
\subsubsection{SET DEFAULT}
La politica \texttt{SET DEFAULT}
sostituisce il valore della foreign key
nelle tuple figlie con il valore
predefinito dell'attributo.
\begin{verbatim}
FOREIGN KEY (sindaco)
REFERENCES persona(cf)
ON DELETE SET DEFAULT
\end{verbatim}
Il valore predefinito deve comunque
rispettare il vincolo di integrità
referenziale.
Ad esempio, se il valore di default
è \texttt{'SCONOSCIUTO'}, deve esistere
una tupla padre con tale chiave.
In caso contrario, l'operazione
può essere rifiutata.
\subsection{Riepilogo delle politiche}
\begin{center}
\begin{tabular}{|l|p{8cm}|}
\hline
\textbf{Politica} & \textbf{Comportamento} \\
\hline
NO ACTION &
Rifiuta l'operazione se il vincolo
risulta violato al momento della verifica. \\
\hline
RESTRICT &
Impedisce immediatamente l'operazione
sulla tupla padre referenziata. \\
\hline
CASCADE &
Propaga automaticamente la cancellazione
o l'aggiornamento alle tuple figlie. \\
\hline
SET NULL &
Imposta a NULL la foreign key
delle tuple figlie coinvolte. \\
\hline
SET DEFAULT &
Imposta al valore di default
la foreign key delle tuple figlie. \\
\hline
\end{tabular}
\end{center}

\section{Transazioni SQL e vincoli differibili}
\subsection{Vincoli DEFERRABLE e DEFERRED}
Normalmente, i vincoli di integrità
vengono controllati al termine
di ogni istruzione SQL.
Tuttavia, in alcune situazioni
può essere utile consentire
temporaneamente una violazione
di un vincolo, purché questa
venga risolta prima della
conclusione della transazione.
SQL permette di ottenere questo
comportamento attraverso i
\textbf{vincoli differibili}.
È importante distinguere:
\begin{itemize}
    \item \textbf{DEFERRABLE}: indica
    che il controllo del vincolo
    può essere posticipato.

    \item \textbf{DEFERRED}: indica
    che il controllo del vincolo
    è effettivamente posticipato
    alla fine della transazione.

    \item \textbf{IMMEDIATE}: indica
    che il vincolo viene controllato
    al termine di ogni istruzione SQL.
\end{itemize}
\noindent Quindi:
\[
\boxed{
\text{DEFERRABLE}
\neq
\text{DEFERRED}
}
\]
Un vincolo può essere dichiarato
\texttt{DEFERRABLE}, ma essere
inizialmente controllato in
modalità \texttt{IMMEDIATE}.
\subsection{Definizione dei vincoli differibili}
Quando si definisce un vincolo,
è possibile specificare:
\begin{verbatim}
DEFERRABLE
\end{verbatim}
oppure:
\begin{verbatim}
NOT DEFERRABLE
\end{verbatim}
Un vincolo \texttt{NOT DEFERRABLE}
non può essere impostato in
modalità \texttt{DEFERRED}.
Per i vincoli differibili,
è inoltre possibile specificare:
\begin{verbatim}
DEFERRABLE INITIALLY IMMEDIATE
\end{verbatim}
oppure:
\begin{verbatim}
DEFERRABLE INITIALLY DEFERRED
\end{verbatim}
Nel primo caso, il vincolo viene
inizialmente controllato dopo
ogni istruzione.
Nel secondo caso, il controllo
viene inizialmente posticipato
alla fine della transazione.
Se non si specifica nulla,
il comportamento predefinito è:
\begin{verbatim}
NOT DEFERRABLE
\end{verbatim}
Se invece si specifica soltanto
\texttt{DEFERRABLE}, il vincolo
è inizialmente \texttt{IMMEDIATE}.
\subsection{SET CONSTRAINTS}
La parola $CONSTRAINTS$ serve a indicare al database che il comando riguarda i vincoli.\\
All'interno di una transazione,
è possibile modificare la modalità
di controllo dei vincoli differibili.\\
Per posticipare il controllo
di un vincolo specifico:
\begin{verbatim}
SET CONSTRAINTS nome_vincolo DEFERRED;
\end{verbatim}
Per posticipare il controllo
di tutti i vincoli differibili:
\begin{verbatim}
SET CONSTRAINTS ALL DEFERRED;
\end{verbatim}
Per tornare alla modalità immediata:
\begin{verbatim}
SET CONSTRAINTS nome_vincolo IMMEDIATE;
\end{verbatim}
\subsection{Vincoli differibili in PostgreSQL}
Non tutti i DBMS supportano
gli stessi tipi di vincoli differibili.
In PostgreSQL possono essere
dichiarati \texttt{DEFERRABLE}
i seguenti vincoli:
\begin{itemize}
    \item \texttt{UNIQUE};
    \item \texttt{PRIMARY KEY};
    \item \texttt{FOREIGN KEY};
    \item \texttt{EXCLUDE}.
\end{itemize}
In particolare, i vincoli
\texttt{NOT NULL} e \texttt{CHECK}
non possono essere dichiarati
\texttt{DEFERRABLE} in PostgreSQL.
Per gli esempi del corso,
i vincoli più importanti sono
quelli di \textbf{foreign key}.

\section{Esempio: vincoli di Foreign Key reciproci}
\subsection{Definizione delle tabelle}
Consideriamo due tabelle:
\begin{itemize}
    \item \texttt{persona}: contiene
    le persone e le rispettive città
    di nascita.

    \item \texttt{citta}: contiene
    le città e i rispettivi sindaci.
\end{itemize}
Le due tabelle hanno vincoli
di foreign key reciproci:
\[
\text{persona.cittanascita}
\rightarrow
\text{citta.nome}
\]
\[
\text{citta.sindaco}
\rightarrow
\text{persona.cf}
\]
Quindi, a seconda del vincolo
considerato, una tabella può
essere sia padre sia figlia.
Definiamo le tabelle:
\begin{verbatim}
CREATE TABLE persona (
    cf VARCHAR(100) PRIMARY KEY,
    cittanascita VARCHAR(30)
);

CREATE TABLE citta (
    nome VARCHAR(30) PRIMARY KEY,
    sindaco VARCHAR(100)
        CONSTRAINT vincolo1
        REFERENCES persona(cf)
);

ALTER TABLE persona
ADD CONSTRAINT vincolo2
FOREIGN KEY (cittanascita)
REFERENCES citta(nome);
\end{verbatim}
Abbiamo quindi:
\begin{itemize}
    \item \texttt{vincolo1}:
    il sindaco di una città deve
    essere una persona esistente.

    \item \texttt{vincolo2}:
    la città di nascita di una persona
    deve essere una città esistente.
\end{itemize}
\noindent Entrambi i vincoli utilizzano
la politica predefinita
\texttt{NO ACTION}.
\subsection{Inserimento dei dati}
Inseriamo due città:
\begin{verbatim}
INSERT INTO citta
VALUES
('Roma', NULL),
('Milano', NULL);
\end{verbatim}
Successivamente inseriamo una persona:
\begin{verbatim}
INSERT INTO persona
VALUES ('100', 'Roma');
\end{verbatim}
L'inserimento è valido perché:
\begin{itemize}
    \item il valore \texttt{NULL}
    dell'attributo \texttt{sindaco}
    è consentito;

    \item la città \texttt{Roma}
    esiste già nella tabella
    \texttt{citta}.
\end{itemize}

\subsection{Problema: cancellazione di Roma}
Supponiamo di voler eliminare
la città di Roma:
\begin{verbatim}
DELETE FROM citta
WHERE nome = 'Roma';
\end{verbatim}
Il DBMS genera un errore perché
la persona con codice fiscale
\texttt{100} ha come città
di nascita \texttt{Roma}.
La cancellazione lascerebbe
una tupla figlia che referenzia
una tupla padre inesistente.
Si avrebbe quindi una violazione
del vincolo \texttt{vincolo2}.
Per risolvere il problema
possiamo utilizzare tre metodi.

\subsection{Metodo 1: aggiornamento manuale}
Il primo metodo consiste
nell'eliminare manualmente
i riferimenti alla città
prima di cancellarla.
Eseguiamo:
\begin{verbatim}
UPDATE persona
SET cittanascita = NULL
WHERE cittanascita = 'Roma';

DELETE FROM citta
WHERE nome = 'Roma';

\end{verbatim}
In questo modo:
\begin{enumerate}
    \item Le persone nate a Roma
    non referenziano più la città.

    \item La città di Roma
    può essere eliminata.

    \item La transazione conferma
    entrambe le operazioni.
\end{enumerate}
\noindent
\textbf{Condizione necessaria:}
l'attributo \texttt{cittanascita}
deve accettare valori \texttt{NULL}.
Il vantaggio è che le persone
rimangono memorizzate nel database.
\subsection{Metodo 2: ON DELETE CASCADE}
Il secondo metodo consiste
nel definire il vincolo
\texttt{vincolo2} con la politica
\texttt{ON DELETE CASCADE}.
La definizione diventa:
\begin{verbatim}
ALTER TABLE persona
ADD CONSTRAINT vincolo2
FOREIGN KEY (cittanascita)
REFERENCES citta(nome)
ON DELETE CASCADE;
\end{verbatim}
Si intende che questa definizione
sostituisce quella precedente
del vincolo \texttt{vincolo2}.
Ora possiamo eseguire:
\begin{verbatim}
DELETE FROM citta
WHERE nome = 'Roma';
\end{verbatim}
Il DBMS elimina automaticamente:
\begin{itemize}
    \item la tupla relativa
    alla città di Roma;

    \item tutte le tuple della
    tabella \texttt{persona}
    che hanno \texttt{Roma}
    come città di nascita.
\end{itemize}
Quindi:
\[
\boxed{
\text{Eliminazione padre}
\Rightarrow
\text{Eliminazione figli}
}
\]
\textbf{Attenzione:} questa soluzione
può essere pericolosa perché
la cancellazione di una città
provoca anche la cancellazione
delle persone nate in quella città.
La politica \texttt{CASCADE}
deve quindi essere utilizzata
soltanto quando questo comportamento
è coerente con il significato dei dati.

\subsection{Metodo 3: vincoli DEFERRABLE}
Il terzo metodo consiste
nel posticipare il controllo
del vincolo di foreign key
alla fine della transazione.
Per farlo, il vincolo deve
essere dichiarato
\texttt{DEFERRABLE}.
Definiamo le tabelle:
\begin{verbatim}
CREATE TABLE persona (
    cf VARCHAR(100) PRIMARY KEY,
    cittanascita VARCHAR(30)
);
CREATE TABLE citta (
    nome VARCHAR(30) PRIMARY KEY,
    sindaco VARCHAR(100)
        CONSTRAINT vincolo1
        REFERENCES persona(cf)
        DEFERRABLE
);

ALTER TABLE persona
ADD CONSTRAINT vincolo2
FOREIGN KEY (cittanascita)
REFERENCES citta(nome)
DEFERRABLE;
\end{verbatim}
Inseriamo i dati:
\begin{verbatim}
INSERT INTO citta
VALUES
('Roma', NULL),
('Milano', NULL);

INSERT INTO persona
VALUES ('100', 'Roma');
\end{verbatim}
Ora vogliamo eliminare Roma,
ma senza modificare i riferimenti
prima della cancellazione.
Possiamo utilizzare:
\begin{verbatim}
BEGIN TRANSACTION;

SET CONSTRAINTS vincolo2 DEFERRED;

DELETE FROM citta
WHERE nome = 'Roma';

UPDATE persona
SET cittanascita = NULL
WHERE cittanascita = 'Roma';

COMMIT;
\end{verbatim}

\subsubsection{Spiegazione dell'esecuzione}
\paragraph{1. Inizio della transazione}
\begin{verbatim}
BEGIN TRANSACTION;
\end{verbatim}
Viene avviata una transazione.
\paragraph{2. Posticipo del controllo}
\begin{verbatim}
SET CONSTRAINTS vincolo2 DEFERRED;
\end{verbatim}
Il controllo del vincolo
\texttt{vincolo2} viene posticipato
alla fine della transazione.
\paragraph{3. Cancellazione di Roma}
\begin{verbatim}
DELETE FROM citta
WHERE nome = 'Roma';
\end{verbatim}
In questo momento, la persona
con codice fiscale \texttt{100}
referenzia una città inesistente.
Si verifica quindi una
\textbf{violazione temporanea}
del vincolo di integrità referenziale.
Tuttavia, l'operazione è consentita
perché il vincolo è in modalità
\texttt{DEFERRED}.
\paragraph{4. Ripristino della consistenza}
\begin{verbatim}
UPDATE persona
SET cittanascita = NULL
WHERE cittanascita = 'Roma';
\end{verbatim}
Il riferimento alla città
eliminata viene rimosso.
La violazione del vincolo
non esiste più.
\paragraph{5. Conferma della transazione}
\begin{verbatim}
COMMIT;
\end{verbatim}
Il DBMS verifica il vincolo
\texttt{vincolo2}.
Poiché il vincolo è soddisfatto,
la transazione viene confermata.
Se invece la violazione
fosse ancora presente,
il commit non potrebbe
essere completato.
\subsection{Differenza tra i tre metodi}
I tre metodi permettono
di gestire la cancellazione
di una tupla padre referenziata,
ma con comportamenti differenti.
\begin{itemize}
    \item \textbf{Metodo 1:}
    si modificano prima
    le tuple figlie e poi
    si elimina la tupla padre.
    \item \textbf{Metodo 2:}
    si utilizza
    \texttt{ON DELETE CASCADE}
    per eliminare automaticamente
    le tuple figlie.

    \item \textbf{Metodo 3:}
    si elimina prima la tupla padre
    e si correggono successivamente
    le tuple figlie, sfruttando
    un vincolo differibile.
\end{itemize}
\noindent La differenza fondamentale
tra il metodo 1 e il metodo 3
è l'ordine delle operazioni.\\
Nel metodo 1:
\[
\boxed{
\text{Aggiorna figli}
\rightarrow
\text{Elimina padre}
}
\]
Nel metodo 3:
\[
\boxed{
\text{Elimina padre}
\rightarrow
\text{Aggiorna figli}
}
\]
